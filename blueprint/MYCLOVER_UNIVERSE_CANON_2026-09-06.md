# myClover Universe Canon — 2026-09-06

**Purpose:** preserve the relationships between old secret/lore objects and current real products while the architecture is rebuilt.

This file is not a visual style guide. It is a canon map: implementation may change routes/UI, but should not accidentally break these meanings.

---

# 1. The house

myClover is no longer best understood as one linear course funnel.

Canonical model:

> **myClover is a living house that reveals itself according to what the visitor does.**

The visitor should not need to understand the whole house before receiving value.

The house may route different people to different rooms while preserving direct links.

---

# 2. Core doctrine

```text
VALUE BEFORE PATH
GIVE BEFORE ASK
SHOW THE TREASURE
PLAYABLE, NOT GAME-LOOKING
SIMPLE → INTERACT → REVEAL → EVOLVE → SAVE → EXPLORE
```

The desired emotional contract:

> **ใครเจอเรา คนนั้นโชคดี**

The visitor should feel value before any conversion request.

# 5. Two entrances to Dungeon

## Build / Proof entrance

```text
BUILD
→ “ขอดูของจริงก่อน”
→ Reward Horizon
→ THE DUNGEON
```

This path should be fast and premium. Do not force a warning ritual just to create friction.

## Curious / Secret entrance

```text
CURIOUS
→ ANOMALY
→ legacy warning threshold
→ voluntary continue
→ THE DUNGEON
```

Same destination, different emotional meaning.

The CURIOUS visitor should feel they found something the house does not normally surface.

# 10. Artifact model

New canon concept:

```text
ARTIFACT
```

Achievement = something the visitor did/unlocked.

Artifact = something that exists across multiple rooms/forms/products.

Canonical first artifact example:

```text
id: teambook-notebook
origin: dungeon
manifestations:
- hidden notebook
- restored notebook
- secret ending / เพื่อนเล่น
- TeamBook.me
```

Future Artifact candidates may include Source/Sauce, FIRST HAND cards, Blacksmith tools and other recurring objects, but do not force everything into this model prematurely.

# 18. Income / private route

Owner has a real operational route for a specific kind of person who urgently needs income and can accept disciplined repetitive work rather than learning/creative work.

This route:

- should not be advertised to everyone
- should only appear when genuine income intent is expressed
- should clearly explain conditions and fit
- should not use guaranteed-income language
- may be capacity-limited only when operational limits are real
- should minimize sensitive financial data collection

Canonical principle:

> **Conditional door, not fake secret/FOMO door.**

This route is not required for P0 Front Door launch.

# 22. Lucky Return

Every route must provide a real piece of value before conversion.

Examples:

```text
Xircle → useful behavioral reflection
Dungeon → exceptional proof/experience
Classroom → usable Source method/insight
X-VISOR → playable system proof
Meet → useful framing/perspective
TeamBook → a useful model for doing something together
```

No route should exist merely to convince the visitor to continue.

---

# 23. Reward Horizon

Before meaningful effort, show what waits at the end.

Especially for old lesson content, the visitor should see the treasure/proof first.

Canonical reversal:

```text
OLD
learn → maybe eventually get reward

NEW
see reward → desire grows → learn how to reach/build it
```

This is the core repackaging strategy for the “library nobody reads” problem.

---

# 24. Save / Return

The house should remember the visitor as soon as a meaningful First Door is found.

Do not require login.

Returning should feel like:

> “บ้านจำได้ว่าคุณเปิดอะไรไว้”

not:

> “เริ่ม onboarding ใหม่”

---

# 25. Final canon statement

> **myClover is not a library that requires visitors to know what to read. It is a living house that gives the most relevant valuable thing first, lets the visitor discover where it came from, remembers what they found, and allows ideas discovered inside the house to become real things outside it.**
