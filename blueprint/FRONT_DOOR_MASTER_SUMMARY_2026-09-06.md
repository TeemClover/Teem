# myClover Adaptive Front Door — Master Summary

**Date:** 2026-09-06  
**Status:** owner-approved product direction  
**Priority:** P0

This is not a homepage redesign.

It is a redesign of **how a stranger enters myClover**.

---

# 1. Absolute objective

The motto:

> **ใครเจอเรา คนนั้นโชคดี**

is a product contract.

Before myClover asks anyone to:

```text
buy
join
register
book
learn
contact
```

the house should already have given them something worth finding.

Every route needs a **Lucky Return**.

No conversion before value.

---

# 2. North Star

> **myClover is a house that reveals itself according to what the visitor does.**

The visitor should feel:

> “เว็บนี้กำลังประกอบตัวเองตามสิ่งที่ฉันเลือก”

Canonical design grammar:

```text
SIMPLE → INTERACT → REVEAL → EVOLVE → SAVE → EXPLORE
```

Canonical interaction principle:

> **Playable, not game-looking.**

---

# 3. Why this exists

myClover does not lack content.

It has strong rooms/assets such as:

```text
/classroom/dungeon/
/classroom/
/xvisor/
/xircle/
/xircle/routinex/
/meet/
CORE7
Forge
TeamBook
Collection
Secret/Awaken lineage
```

The problem is activation and packaging:

> A stranger does not know which valuable thing is relevant enough to spend effort on.

The old library/course model makes the visitor use energy before seeing the reward.

The new model reverses it:

```text
VALUE
→ TREASURE / REWARD HORIZON
→ DESIRE TO CONTINUE
→ PATH
→ DEEP KNOWLEDGE
```

Do not reduce intellectual depth.

Reduce activation energy.

# 5. Positioning

Internal creative position:

> **AI Experience Architect**

Do not lead the homepage with the title.

Let the visitor experience the work first and only later discover who authored it.

The durable position is not “เก่ง Astra.”

It is:

> **คนที่รู้ว่าจะสั่ง AI ให้สร้างอะไรที่คนอยากใช้จริง**

---

# 6. First 60 seconds

Target:

```text
first meaningful interaction: within 5 seconds
First Door: typically within 20–45 seconds
choices before First Door: target 2, max 3
no login
no typing
no survey feeling
no mandatory video
no full navigation before first choice
```

Every touch must visibly matter.

---

# 7. State 0

The first viewport should not explain the whole ecosystem.

Working concept:

```text
MYCLOVER · บ้านที่เปลี่ยนตามคุณ

หน้านี้ยังสร้างไม่เสร็จ

เลือก 1 อย่าง
แล้วดูว่าเว็บนี้จะประกอบตัวเองไปทางไหน
```

Working intent families:

```text
ตัวฉัน
สิ่งที่กำลังสร้าง
คนของฉัน
งานและรายได้
ลองของที่คิดว่าฉันน่าจะชอบ
```

These are user needs, not product names.

Do not present them as a generic 4/5-card SaaS grid.

They should feel like pieces of an unfinished page that become part of the final composition.

---

# 8. First click

This is the most important visual milestone.

The visitor must immediately perceive:

> **I touched this → the website became this.**

The reaction may combine:

```text
GUI reconstruction
layout reconstruction
route geometry
VFX
sound wake
copy response
atmosphere shift
new structure mounting into place
```

Immediate perceived response target: ~<150ms.

Decorative motion may continue without blocking the next action.

---

# 9. Give Before Ask

Hard rule:

> **After Choice 1, give something back before asking another question.**

Never show:

```text
Question 2 of 5
```

Instead return:

- useful interpretation
- insight
- tiny proof
- meaningful preview
- interactive fragment

Then the next choice should feel natural.

---

# 10. Lucky Return

Every route needs an early value event.

Examples:

```text
Xircle
→ a new way to see yesterday / behavior

RoutineX
→ useful repeat/routine framing

Meet
→ useful human perspective

X-VISOR
→ playable system proof

Classroom
→ a usable Source/Sauce idea

Dungeon
→ the exceptional experience itself

TeamBook
→ a useful mental model of doing something together
```

A visitor should be able to leave after one visit and still think:

> “ดีที่กดเข้ามา”

---

# 11. Reward Horizon

Before asking for meaningful effort, show the treasure waiting at the end.

This is crucial for fixing the old lesson wall.

Bad:

```text
read 12 minutes
→ maybe later understand why
```

Better:

```text
see what waits at the end
→ understand why the next 12 minutes are worth it
```

For AI/Build, THE DUNGEON is the strongest reward horizon.

Show a real fragment/preview, not a generic lock icon.

# 12. Working route families

## SELF

```text
เห็นให้ชัด
→ Xircle

ทำให้ต่อเนื่อง
→ RoutineX

อยากมีคนช่วยดู
→ Meet
```

## BUILD

```text
ขอดูของจริงก่อน
→ THE DUNGEON

อยากเริ่มสร้างเอง
→ Classroom
```

## PEOPLE

```text
human/help
→ Meet

system/team/organization
→ X-VISOR

do something together
→ TeamBook
```

## INCOME

This is a real separate intent, not necessarily the same as “business.”

Possible meanings:

```text
build skill
build business
structured repetitive work
urgent need
```

A private/limited route may exist for qualified people who genuinely need income and accept the conditions.

Do not advertise it to everyone.

Do not use guaranteed-income language.

Do not fake scarcity.

P0 does not need to build this route fully.

## CURIOUS

```text
ลองของที่คิดว่าฉันน่าจะชอบ
→ ANOMALY
→ legacy warning
→ THE DUNGEON
```

No extra normal questionnaire required.

# 16. Visual / GUI / VFX / SFX quality bar

These are core product requirements, not polish.

The target is:

> **exclusive by craft, not by paywall**

High-end means:

- exceptional art direction
- exceptional typography
- physical-feeling motion
- causal transitions
- intentional silence
- subtle sound depth
- route-specific atmosphere
- advanced tech only where it creates perceptual value
- world-class fallback on weaker/reduced-motion devices

Do not solve “high-end” by adding more particles, bloom, glass, neon or scroll hijacking.

The visitor should think:

> “ใครทำวะเนี่ย”

not:

> “เอฟเฟกต์เยอะดี”

Practical quality test:

> Is something in the first 10–20 seconds worth screen-recording without us asking them to share?

---

# 17. Technology strategy

Use the right layer for the right job:

```text
DOM/HTML → semantics, copy, buttons, accessibility
CSS → layout, masks, compositing, transitions
SVG → route lines, clover topology, precise vector geometry
Canvas/WebGL → atmosphere, displacement, generative depth
WebGPU → optional top-tier enhancement, not foundation
Web Audio → route/interaction sonic system after user gesture
View Transitions → progressive enhancement for state/page morphs
```

Capability tiers:

```text
CINEMATIC
PREMIUM
ESSENTIAL LUXURY
```

Even the lowest tier must look intentionally premium, not like a broken fallback.

---

# 18. Sound

Before first touch:

```text
house asleep / silent
```

After first user gesture:

```text
AudioContext wakes
→ restrained “house awake” cue
```

Do not autoplay loud sound or music.

CURIOUS/ANOMALY should use subtraction first:

```text
normal ambience
→ collapse toward silence
→ low distant signal
→ threshold artifact
```

Silence can feel more exclusive than louder effects.

---

# 19. Performance

The flagship cannot feel premium if it loads slowly.

Do not preload the whole house.

Progressive prediction:

```text
State 0
→ load only first scene

Choice 1 known
→ prefetch likely branch

Choice 2 known
→ prefetch destination-critical assets
```

The expensive technology must never become friction.

The new root should not casually inherit unrelated global patch imports.

---

# 20. Save Point

Save when First Door is found, not after destination completion.

No login.

The visitor has already given enough intent for personalization.

The desired feeling:

> “กูเริ่มไปแล้ว”

not:

> “กูกำลังจะเริ่ม onboarding”

---

# 21. Returning root

New visitor:

```text
/ → assemble house → First Door → Save
```

Returning visitor:

```text
/ → Personalized Home
```

Do not replay first-run automatically.

Minimum returning model:

```text
WELCOME BACK

คราวก่อนคุณเปิด...

[ ไปต่อ ]
[ ดูบ้าน ]
[ ประกอบใหม่ ]
```

Legacy users with meaningful old progress should be recognized.

---

# 26. Anti-goals

Do not:

- redesign every room before Front Door works
- make a second Dungeon
- clone Dungeon visuals globally
- ask 10 segmentation questions
- require sign-up to save
- put runtime AI/chat at the center of V1
- show every product in the first viewport
- make Home a catalogue
- force the old Main Quest
- make WebGPU a requirement
- build slow decorative 3D for its own sake
- make Astra branding louder than myClover
- guarantee income on a private route

---

# 27. Acceptance test

Open on a clean phone and ask:

### Before first touch

> **ถ้าไม่รู้จัก myClover เลย อยากกดอะไรภายใน 5 วินาทีไหม?**

If no: fix State 0. Do not add explanation.

### After first touch

> **เห็นไหมว่าการกระทำของฉันเปลี่ยนเว็บจริง?**

If no: fix causality. Do not add Question 2.

### At First Door

> **รู้สึกไหมว่าประตูนี้เกิดจากสิ่งที่ฉันเลือก ไม่ใช่โฆษณาที่ถูกยัดให้?**

If no: fix route/reason/reveal.

### After leaving

> **ถ้าวันนี้ไม่มีเวลา รู้สึกว่าอยากกลับมาทำให้จบไหม?**

If no: fix value/reward/save.
