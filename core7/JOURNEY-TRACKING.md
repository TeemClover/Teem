# Journey Tracking — คู่มือต่อสาย

ตัวรับข้อมูลของเส้นทาง First Run พร้อมใช้แล้ว หน้าเว็บฝั่ง Journey ยังไม่มี
เอกสารนี้บอกว่าเมื่อสร้างหน้าพวกนั้นแล้ว ต้องเรียกอะไรตรงไหน

ทำตัวรับมาก่อนหน้าโดยตั้งใจ เพราะ **event ที่ไม่ได้เก็บวันนี้ คือข้อมูลที่
ย้อนกลับไปเก็บไม่ได้ตลอดไป** ถ้าหน้าเสร็จก่อนแล้วค่อยมาต่อสาย ช่วงแรกที่คน
เดินผ่านมากที่สุดจะไม่มีตัวเลขให้ดูเลย

---

## 1. ยิง event

```js
import { reportJourneyStep } from '/core7/js/analytics.js';

reportJourneyStep('FORGE_EP_1_COMPLETE');
```

เท่านี้พอ — ฟังก์ชันจัดการให้ทั้งหมด:

- **กันซ้ำในตัว** นับ "เครื่องที่ผ่านขั้นนี้" ไม่ใช่ "กดกี่ครั้ง" คนกด Back
  แล้วอ่านซ้ำจะไม่ทำให้ตัวเลขบวม ถ้าอยากได้ทุกครั้งจริง ๆ ส่ง `{ once: false }`
- **ยิงทิ้งไม่รอผล และไม่ throw** เน็ตล่มต้องไม่ทำให้หน้าเว็บค้าง
- **แนบแฟล็กทางเข้าให้เอง** ไม่ต้องส่งมาเอง

## 2. ขั้นทั้งหมด

เรียงตามลำดับที่คนเดินจริง แหล่งความจริงอยู่ที่ `JOURNEY_STEPS` ใน
`core7/backend/analytics-v11.js` — เพิ่มขั้นใหม่ที่นั่นที่เดียว ทั้งชุดที่ยอมรับ
ลำดับบนกราฟ และป้ายภาษาไทยจะตามไปเอง

| Event | ยิงตอนไหน |
|---|---|
| `JOURNEY_START` | เข้าประตูหน้าแรก |
| `PROLOGUE_COMPLETE` | อ่านบทนำ 4 ช่องจบ |
| `FORGE_EP_1_COMPLETE` … `FORGE_EP_7_COMPLETE` | อ่านการ์ตูนแต่ละตอนจบ |
| `SAVEPOINT_BLACKSMITH` | ถึงหน้า Save Point |
| `QUICK_WALKTHROUGH_COMPLETE` | อ่าน Quick Walkthrough จบ |
| `CORE7_ONBOARDING_START` | เข้าหน้าเลือกมือของ First Run |
| `CORE7_ONBOARDING_COMPLETE` | เล่น Match แรกจบ |
| `LOADOUT_VIEW` | เห็นหน้า Loadout |
| `LESSON_1_START` | กดเข้าบทที่ 1 |

## 3. แฟล็กทางเข้า

CORE7 **เปิดให้ทุกคนเข้าตรงได้เสมอ** แฟล็กนี้ไม่ได้กั้นใคร มีไว้แยกตัวเลข
ตอนอ่านอย่างเดียว — คนที่เดินมาตามเส้นกับคนที่ได้ลิงก์จากเพื่อนควรถูกอ่าน
คนละแบบ ไม่งั้น conversion เพี้ยนทั้งกระดาน

ส่งคนเข้าเส้นด้วย query string ครั้งเดียว:

```
/core7/hand/?entry=forge&next=bot&level=easy
```

จากนั้นค่าถูกจำไว้ในเครื่อง (`c7:entry`) และติดไปกับ **ทุก** event หลังจากนั้น
รวมถึง `MATCH_START` / `MATCH_COMPLETE` ของ CORE7 เอง — แฟล็กหลุดทันทีที่กด
ลิงก์ถัดไปถ้าไม่จำไว้ แล้วสถิติจะเห็นแค่ครึ่งเดียว

ค่าที่ยอมรับมีแค่ `forge` อย่างอื่นถูกทิ้งเป็น `null` ที่ฝั่ง backend
เพื่อไม่ให้คอลัมน์นี้กลายเป็นถังขยะที่ใครยัดอะไรก็ได้เข้ามา

เมื่อคนเดินจบเส้นแล้ว (เข้าบทที่ 1) เรียก `clearEntry()` เพื่อไม่ให้เขาถูกนับ
เป็น Journey ไปตลอด

```js
import { clearEntry } from '/core7/js/analytics.js';
clearEntry();
```

## 4. ดูผล

`/stat/journey/` — บันไดขั้น, % ที่ผ่านต่อในแต่ละขั้น, จุดที่คนหายเยอะสุด,
ตารางแยก forge/direct และรายวัน

ตราบใดที่ยังไม่มีหน้าไหนยิง event หน้านั้นจะขึ้นคำเตือนว่า **"ยังไม่ได้ต่อสาย"**
เพื่อไม่ให้อ่านเลขศูนย์ผิดเป็น "ไม่มีคนเดิน"

API: `GET /api/core7/journey-stats?from&to`

## 5. ข้อควรรู้ตอนอ่านตัวเลข

- นับด้วย Anonymous Installation ID แบบสุ่มในเครื่อง **ไม่ใช่จำนวนคนจริง**
  เปลี่ยนเบราว์เซอร์หรือล้างข้อมูลคือคนละหัว ตัวเลขเป็นขอบล่างเสมอ
- แต่ละขั้นไม่ได้บังคับว่าต้องผ่านขั้นก่อนหน้าจริง **ถ้าขั้นหลังมีมากกว่าขั้นหน้า
  แปลว่ามีทางลัดที่ไม่ได้ตั้งใจ** — เป็นเรื่องที่ต้องเห็น ไม่ใช่เรื่องที่ต้องกลบ
  ด้วยการบังคับให้กราฟลดทางเดียว
- ไม่เก็บชื่อ อีเมล หรือ IP

## 6. Act และ Achievement

คนละระบบกับ Journey Step ข้างบน — Journey Step วัด "เดินถึงขั้นไหน"
ส่วน Act/Achievement วัด "ทำอะไรไปบ้าง"

ทะเบียนอยู่ที่ `assets/achievements.js` เพิ่มของใหม่ที่นั่นที่เดียว

**ยิง Act โดยไม่ต้องเขียน JS** — ใส่ใน HTML แล้ว `assets/track.js` จัดการเอง

```html
<meta name="mc-act-view" content="home-open">
<button data-mc-act="home-video">▶ ดูคลิป</button>
<script type="module" src="/assets/track.js"></script>
```

**ยิง Achievement จากโค้ด**

```js
import { reportAchievementUnlock } from '/core7/js/analytics.js';
reportAchievementUnlock('forge-intro');   // กันซ้ำในตัว
```

ดูผลที่ `/collection/stat/` · API: `GET /api/core7/achievement-stats?from&to`
