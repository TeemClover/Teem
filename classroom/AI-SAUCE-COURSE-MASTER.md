# 1. ชื่อและตำแหน่งของหลักสูตร

## ชื่อหลัก

# AI ใส่ซอส

## ชื่ออธิบาย

**Source-Based AI Workflow**

## คำสัญญาของหลักสูตร

หลักสูตรนี้ไม่ได้เริ่มจากการสอนให้ผู้เรียนเขียน Prompt ยาวขึ้น หรือจำสูตรคำสั่งวิเศษ

หลักสูตรนี้สอนให้ผู้เรียน:

1. หยิบความรู้ ประสบการณ์ เอกสาร ไฟล์ เสียง ภาพ และบทสนทนาที่มีอยู่มาเป็นวัตถุดิบ
2. คัดสิ่งสำคัญออกจากสิ่งที่ไม่จำเป็น
3. ปรุงให้กลายเป็น Source ที่ชัด ตรวจได้ และพร้อมใช้
4. บรรจุ Source เป็นไฟล์ `.md`
5. เลือกเครื่องปรุงที่เหมาะกับงาน
6. ออกแบบ Workflow ให้ AI ตัวใดก็ได้ช่วยทำงานต่อ
7. ชิม ตรวจ แก้ และส่งงานออกไปใช้ในโลกจริง

## Positioning

> **หลักสูตร AI ที่เอาเชฟมาช่วยสอนเรื่อง Source และ Workflow โดยไม่เริ่มจากการสอนเขียน Prompt**

คำว่า “หลักสูตรแรก” สามารถใช้เป็น Brand Claim ได้เมื่อผ่านการตรวจสอบก่อนเผยแพร่ในโฆษณาที่อ้างข้อเท็จจริงต่อสาธารณะ แต่ในเนื้อเรื่องของ myClover ให้เล่าอย่างมั่นใจว่า:

> เราไม่ได้พาเชฟมาสอนเขียน Prompt  
> เราพาเชฟมาช่วยทำให้เรื่อง AI ที่ย่อยยาก กินง่ายพอที่คนธรรมดาจะกินหมดจาน

# 2. คนที่เขียนหลักสูตรนี้

หลักสูตรนี้ถูกเขียนขึ้นโดยคน 2 คนจากโลกเดียวกัน

## 2.1 คนจากการ์ตูน 7 ตอน

คนแรกคือคนที่ผู้เรียนเพิ่งอ่านเรื่องของเขามาตลอด Webtoon 7 ตอน

เขาเป็นคนที่:

- เริ่มจากกระดาษ A4
- เรียงความคิดที่กระจัดกระจายให้คนอื่นเข้าใจ
- เปลี่ยนคำตอบเป็นเครื่องมือ
- เปลี่ยนสิ่งที่พูดเพียงครั้งเดียวให้กลายเป็น Source
- คัดสิ่งที่ไม่จำเป็นออก
- ทำ Starter Kit ให้คนใหม่ไม่ต้องเริ่มจากศูนย์
- ใช้หลักการเดิมสร้างเว็บไซต์ ห้องเรียน การ์ตูน และเกมด้วย AI ในปี 2026

เขาเก่งเรื่องระบบ แต่มีปัญหาหนึ่ง

> บางครั้งภาษาของเขาเข้าใจง่ายสำหรับคนที่คิดแบบเดียวกัน  
> และยากเกินไปสำหรับคนที่ไม่ได้โตมากับเกม ระบบ และการรื้อของเป็นชิ้นส่วน

## 2.2 เชฟมืออาชีพที่โผล่มาในตอน 7

คนที่ 2 คือ “เชฟ”

เชฟไม่ต้องมีชื่อบนหน้าหลักสูตร ใช้คำว่า **เชฟ** อย่างเดียว

เชฟมีหน้าที่:

- ชิมว่าคำอธิบายนี้คนทั่วไปกินลงหรือไม่
- แปลศัพท์เทคนิคให้เห็นภาพ
- หยุดคนเขียนเมื่อเริ่มอธิบายเหมือนกำลังวางระบบหลังบ้านให้วิศวกร 40 คน
- เตือนว่าเนื้อหาที่ถูกต้องแต่กินไม่หมดจาน ก็ยังส่งไม่ถึงคนอ่าน
- พูดสุภาพ แต่ไม่จำเป็นต้องถนอมน้ำใจแนวคิดที่ยังไม่อร่อย

ตัวอย่างเสียงของเชฟ:

> **เชฟชิมแล้ว:** ข้อมูลครบดีค่ะ แต่ตอนนี้เหมือนยกครัวทั้งครัวมาเสิร์ฟบนจานเดียว คนอ่านไม่ได้หิวขนาดนั้นนะคะ

> **เชฟชิมแล้ว:** เขียน Prompt 4 หน้า แต่ไม่บอกว่าลูกค้าแพ้กุ้ง งานก็ยังพังได้เหมือนเดิมค่ะ

> **เชฟชิมแล้ว:** มีเครื่องปรุงเยอะไม่ได้แปลว่าอร่อยนะคะ เทหมดลิ้นชักลงหม้อ เขาเรียกทำลายหลักฐานค่ะ

## 2.3 เหตุผลที่ต้องมีทั้ง 2 คน

คนหนึ่งรู้ว่าระบบต้องทำงานอย่างไร

อีกคนรู้ว่าคนจะยอมกินมันหรือไม่

> **ระบบทำให้งานทำซ้ำได้**  
> **รสมือทำให้คนอยากกลับมากินอีก**

หลักสูตรนี้จึงต้องรักษาทั้ง 2 อย่างพร้อมกัน

# 3. หลักคิดใหญ่: Source คือวัตถุดิบ

## ภาษาหลักของหลักสูตร

| คำในระบบ AI | ภาษาครัวของหลักสูตร | ความหมาย |
|---|---|---|
| Source | วัตถุดิบ | ความรู้ ข้อมูล ตัวอย่าง กติกา ประสบการณ์ และข้อห้ามที่ AI ต้องใช้ |
| Source ที่คัดและจัดแล้ว | ซอส | วัตถุดิบที่ผ่านการเลือก จัดโครงสร้าง ตรวจ และปรุงให้พร้อมใช้ |
| `.md` | ขวด | ภาชนะข้อความที่เก็บซอสและส่งต่อข้ามแชตหรือข้าม AI ได้ง่าย |
| Prompt | เครื่องปรุง / ฉลาก | คำสั่งเฉพาะหน้าที่เพิ่มรส กำหนดบทบาท รูปแบบ หรือภารกิจ |
| Prompt Library | ลิ้นชักเครื่องปรุง | ชุดคำสั่งสำเร็จรูปที่หยิบใช้ตามงาน ไม่ใช่เททั้งหมดลงไป |
| Workflow | สูตรและลำดับในครัว | ใครรับอะไร ทำอะไรก่อนหลัง ตรวจตรงไหน และส่งต่อให้ใคร |
| AI | ผู้ช่วยในครัว | ลงมือเร็ว แตกงานได้มาก แต่ยังต้องได้รับวัตถุดิบและคำตัดสินจากมนุษย์ |
| Output | จานที่เสิร์ฟ | งานที่ออกจากแชตไปอยู่ในโลกจริง |
| Feedback | การชิม | ข้อมูลกลับมาว่าอะไรถูก อะไรจืด อะไรเกิน และต้องแก้ตรงไหน |
| Iteration | ปรับรส | แก้เฉพาะจุดจากสิ่งที่ชิม ไม่รื้อของดีทิ้งทุกครั้ง |
| Hallucination | หยิบของที่ไม่มีในครัวมาใส่ | AI เติมสิ่งที่ Source ไม่ได้ให้ หรือพูดอย่างมั่นใจเกินหลักฐาน |
| Definition of Done | หน้าตาจานก่อนออกจากครัว | เกณฑ์ว่างานแบบไหนถือว่าเสร็จและเสิร์ฟได้ |

## ประโยคหลัก

> **Source คือวัตถุดิบ**  
> **ซอสคือ Source ที่ปรุงจนพร้อมใช้**  
> **`.md` คือขวดที่ AI เปิดกินและย่อยต่อได้ง่าย**

## คำอธิบายที่ต้องแม่น

ใช้ประโยค “AI กิน `.md` แล้วย่อยง่ายที่สุด” เป็น Metaphor สำหรับผู้เริ่มต้นได้

แต่เมื่อกดอ่านเพิ่ม ต้องอธิบายอย่างตรงไปตรงมาว่า:

- AI หลายระบบอ่าน PDF, DOC, PPT, ภาพ เสียง และวิดีโอได้
- `.md` ไม่ได้ทำให้งานดีเองโดยอัตโนมัติ
- ข้อดีของ `.md` คือโครงสร้างข้อความตรง ไฟล์เล็ก แก้ง่าย ค้นง่าย เปรียบเทียบ Version ง่าย และส่งต่อข้ามเครื่องมือได้สะดวก
- PDF ถูกออกแบบเพื่อรักษาหน้าตาของเอกสารสำหรับมนุษย์
- Markdown เหมาะกับการรักษาลำดับและโครงสร้างความหมายเพื่อใช้ทำงานต่อ
- ถ้าวัตถุดิบผิด ซอสในขวด `.md` ก็ยังผิดได้

> **เชฟชิมแล้ว:** เปลี่ยนขวดสวยขึ้นไม่ได้ช่วยอะไร ถ้าข้างในยังเป็นน้ำล้างหม้อนะคะ

# 4. สิ่งที่หลักสูตรนี้ไม่ทำ

1. ไม่ผูกหลักสูตรกับ AI ตัวใดตัวหนึ่ง
2. ไม่เริ่มจากหน้าสมัครบัญชี
3. ไม่ทำให้ Prompt เป็นพระเอก
4. ไม่สอนให้เชื่อ AI โดยไม่ตรวจ
5. ไม่อ้างว่า Source ที่ดีทำให้ AI ถูก 100%
6. ไม่สอนให้ใช้เครื่องมือเยอะเพื่อให้ดูเก่ง
7. ไม่ใช้ภาษาเกมเป็นกำแพงด่านแรกของคนทั่วไป
8. ไม่เปลี่ยน myClover ทั้งบ้านให้เป็นร้านอาหาร

โลกภายนอกยังเป็น **บ้านแบบเล่นได้**

ห้องเรียนคือ **ครัว AI ใส่ซอส**

บทที่ 7 คือ **ประตูหลังครัวที่เปิดให้เห็นกลไกจริง**

ตอนพิเศษคือ **โลกของคนที่ยังอยู่หลังเครื่องมือทั้งหมด**

# 5. รูปแบบ UX ของทุกบท

ทุกบทต้องมีโครงคล้ายกัน เพื่อให้ผู้เรียนไม่ต้องเรียนหน้าจอใหม่ทุกครั้ง

## 5.1 Hero

- ภาพประกอบคุณภาพสูงในโลกครัว AI
- จาน ซอส วัตถุดิบ หรือทีมหลังครัวต้องสัมพันธ์กับ Mechanic ของบท
- ใช้ภาพมากขึ้นกว่าคอร์สเดิม แต่ภาพต้องช่วยอธิบาย ไม่ใช่ใส่เพราะพื้นที่ว่าง
- สไตล์ภาพให้ต่อยอดจากภาพบทที่ 1 และภาพเอโกะในครัว: อบอุ่น สะอาด Premium มีเทคโนโลยีแบบโปร่งใส ไม่เป็น Cyberpunk รกตา

## 5.2 TL;DR

Always Show ตั้งแต่ต้น

ตอบให้ครบในพื้นที่สั้น:

- วันนี้ทำอะไร
- ต้องมีอะไร
- จบแล้วได้อะไรกลับบ้าน
- ใช้เวลาประมาณเท่าไร

TL;DR ต้องทำให้คนขี้เกียจอ่านเริ่มลงมือได้ แต่เขียนให้มี Hook จนรู้สึกว่าอ่านต่อแล้วน่าจะได้ของมากกว่า

## 5.3 เมนูวันนี้

สรุป Mechanic ของบทด้วยภาษาครัว

## 5.4 วัตถุดิบที่ต้องมี

ใช้ของจากบทก่อน หรือเริ่มจากไฟล์ของตัวเองได้

## 5.5 ขวดซอส / เครื่องปรุงประจำบท

แจก Prompt หรือ Template เป็นวัตถุที่มองเห็นได้:

- ขวด
- ซอง
- กระปุก
- Recipe Card
- Checklist

ห้ามเรียกกองรวมว่า Prompt Library บนหน้าหลัก

## 5.6 ลงมือปรุง

Always Show เป็นขั้นตอนสั้น ชัด และทำตามได้ทันที

## 5.7 เชฟชิมแล้ว

กล่องแปลศัพท์หรือจิกปัญหาที่คนมักพลาด

กฎเสียง:

- เรียกตัวเองว่า “เชฟ”
- พูดสุภาพ
- ไม่ใช้ชื่อบุคคล
- ไม่ด่าผู้เรียน
- จิกพฤติกรรมหรือระบบ ไม่จิกคุณค่าของคน
- ปิดด้วยประโยคที่ช่วยให้แก้ต่อได้

## 5.8 หลังครัว

ปุ่มขยาย Optional Reading

ใช้สำหรับ:

- กลไกเชิงเทคนิค
- เหตุผลที่ช่วยประหยัดเวลา
- เหตุผลที่ช่วยประหยัดเครดิต
- ความเสี่ยง
- ข้อจำกัด
- ตัวอย่างยาว
- เรื่องเล่าที่อ่านสนุกแต่ไม่จำเป็นต่อการทำภารกิจ

## 5.9 เครื่องมือในหน้า

ทุกบทควรมีเครื่องมือเล็กที่ทำงานบน Browser เท่าที่เหมาะสม เช่น:

- เครื่องบรรจุ `.md`
- เครื่องรวมเครื่องปรุง
- เครื่องสร้าง Recipe Card
- เครื่องตรวจหัวข้อที่ขาด
- เครื่องดาวน์โหลด Source / Workflow

ต้องบอกตรงไปตรงมาว่าเครื่องมือใดมี AI จริง หรือเป็นเพียงการจัดข้อความในเครื่อง

## 5.10 ห่อกลับบ้าน

ทุกบทต้องจบด้วยของจริงที่ Download หรือเปิดใช้ต่อได้

# 7. บทที่ 1 — เริ่มจากการปรุงซอส

## Mechanic

**SOURCE — สร้างหัวซอสขวดแรก**

## เป้าหมาย

ผู้เรียนจบด้วย Source ที่เป็นของตัวเอง ไม่ใช่จบด้วยความรู้ว่า AI คืออะไร

## จุดเริ่มต้นที่รองรับ

ผู้เรียนเริ่มจากสิ่งใดก็ได้:

- เปิด Voice แล้วเล่า
- PDF
- PowerPoint
- Word
- Spreadsheet
- ภาพ
- เสียง
- วิดีโอ
- โน้ต
- เว็บไซต์
- ข้อความที่ก๊อปมา
- แชต Session เดิม
- หลายอย่างปนกัน

## เส้นทางหลัก

1. เทวัตถุดิบ
2. ให้ AI สร้าง Source ฉบับแรก
3. อ่านและชิม
4. เติมสิ่งที่ขาด
5. ตัดสิ่งที่ไม่ใช่
6. แยกเรื่องที่รู้ เรื่องที่เดา และเรื่องที่ยังไม่ตัดสินใจ
7. ปรุงให้ถูกงาน
8. บรรจุเป็น `.md`
9. ส่งไปทดสอบในแชตใหม่
10. ให้ AI สรุปสิ่งที่เข้าใจและรอการยืนยันก่อนทำงาน

## หัวซอส

หัวซอสไม่ใช่ “สรุปเอกสาร”

หัวซอสตอบคำถามว่า:

> จากของทั้งหมดนี้ AI ต้องรู้อะไร เพื่อทำงานชิ้นต่อไปให้ถูก?

หัวซอสควรมี:

- เป้าหมาย
- ผู้ใช้หรือผู้รับงาน
- ข้อมูลสำคัญ
- สิ่งที่ตัดสินใจแล้ว
- สิ่งที่ห้ามเปลี่ยน
- ตัวอย่าง
- น้ำเสียง
- ข้อจำกัด
- งานที่เสร็จแล้ว
- งานที่ยังค้าง
- Definition of Done
- เรื่องที่ยังไม่รู้และห้ามเดา

## ขวดประจำบท

1. ขวดเทวัตถุดิบ
2. ขวดสกัดหัวซอสจากไฟล์
3. ขวดสกัดหัวซอสจากแชตเดิม
4. ขวดปรุงให้ถูกงาน
5. ขวดชิมและแก้รส
6. ขวดบรรจุ `.md`

## เครื่องบรรจุขวดซอส

ซ่อนไว้ในปุ่มขยาย แต่เข้าถึงง่าย

ใช้เมื่อ AI ที่ผู้เรียนใช้ไม่สร้างไฟล์ `.md` ให้ดาวน์โหลด

Flow:

1. ก๊อปข้อความ Markdown จาก AI
2. วางลงช่อง
3. ตั้งชื่อไฟล์
4. กด **“สกัดใส่ขวดซอส.md”**
5. ดาวน์โหลดลงเครื่อง
6. นำไฟล์ไปส่งต่อให้ AI ตัวอื่นหรือแชตใหม่

ต้องมีปุ่มลอกกรอบ Code Fence ออก และแจ้งว่าเครื่องมือนี้ไม่ได้ส่งข้อความขึ้น Server

# 8. บทที่ 2 — ชิมก่อนเติม

## Mechanic

**TASTE — ตรวจว่า AI เข้าใจรสเดียวกับเราหรือยัง**

## เหตุผลที่ใช้ภาพ

ภาพทำให้ความเข้าใจผิดมองเห็นได้ทันที

ถ้า AI เข้าใจ Source ไม่ครบ มันอาจ:

- เปลี่ยนหน้าคน
- เปลี่ยนเสื้อ
- ใส่ของที่ห้ามมี
- ใช้สีผิด
- ทำบรรยากาศผิดยุค
- ลืมสิ่งสำคัญ
- เติมสิ่งที่ไม่มีในเรื่อง

ภาพจึงไม่ใช่เพียง Output สวยๆ

ภาพคือ **ช้อนชิม Source**

## เส้นทางหลัก

1. แนบ Source จากบทที่ 1
2. เลือกภาพทดสอบ 1 ภาพที่ตรวจเรื่องสำคัญได้หลายข้อ
3. ให้ AI สร้าง Version แรก
4. แยกข้อผิดพลาดเป็น 3 กลุ่ม
   - Source ยังไม่ได้บอก
   - Source บอกแล้วแต่ AI ทำผิด
   - ผู้เรียนเพิ่งตัดสินใจใหม่หลังเห็นภาพ
5. แก้ Source ก่อนแก้ Prompt ยาวๆ
6. สร้าง Version ถัดไป
7. เก็บ Canon และข้อห้ามกลับเข้าขวด

## ขวดและเครื่องปรุง

- ขวด Visual Canon
- ขวด Character / Product Reference
- ผงคุมยุค
- ผงคุมสี
- ผงคุมสิ่งที่ห้ามมี
- การ์ด Surgical Edit: แก้เฉพาะจุด ห้ามรื้อสิ่งที่ผ่านแล้ว

## เชฟชิมแล้ว

> ภาพสวยค่ะ แต่เป็นคนละคน คนละบ้าน และคนละปี นี่ไม่เรียกว่าปรับรสนะคะ นี่เปิดร้านใหม่แล้วค่ะ

## ของกลับบ้าน

- ภาพทดสอบ 1 ภาพ
- Visual Canon
- Negative / Do-not-change list
- Source Version ที่แก้จาก Feedback จริง

## Reward

**TASTE CHECK PASSED**

## ภาพประกอบ

1. จาน 2 ใบ: จานแรกสวยแต่ผิดสูตร จานที่ 2 ตรง Source
2. เชฟใช้ช้อนชิม พร้อม Checklist ลอยข้างจาน
3. ภาพ Version ก่อนและหลังแบบ Surgical Edit
4. ตู้ Canon เก็บสี เสื้อ พร็อพ และสิ่งห้ามเปลี่ยน

# 11. บทที่ 5 — เปิดลิ้นชักเครื่องปรุง

## Mechanic

> แล้วจัดเป็นสูตรพร้อมใช้ซ้ำ

## ลิ้นชักเครื่องปรุง

Prompt Vault เดิมเปลี่ยนสถานะเป็น **ลิ้นชักเครื่องปรุง**

Prompt ไม่ใช่อาหารหลัก

Prompt เป็นสิ่งที่เพิ่มรสหรือกำหนดงาน เช่น:

- ผงน้ำเสียง

- ผงตรวจข้อเท็จจริง
- ผงคุม Canon
- ผงกำหนดบทบาท
- ผงวิจารณ์
- ผงสรุป
- ผงส่งต่อ
- ผง Definition of Done
- ผงถามเมื่อข้อมูลไม่พอ

## Recipe Card

ผู้เรียนจัดว่า:

1. ใช้ Source ขวดใด
2. หยิบเครื่องปรุงใด
3. ใส่อะไรก่อนหลัง
4. ให้ AI ตัวใดรับหน้าที่ใด

7. Output แบบไหนถือว่าเสร็จ

## เชฟชิมแล้ว

> มีเครื่องปรุงเยอะไม่ได้แปลว่าอร่อยนะคะ เทหมดลิ้นชักลงหม้อ เขาเรียกทำลายหลักฐานค่ะ

> Prompt ไม่ใช่อาหารหลักค่ะ ถ้าใส่ทั้งซองทุกจาน ไม่ได้แปลว่ารสชัด แปลว่าไตทำงานหนักค่ะ

### หัวข้อ

## ผมรู้จัก `.md` จากคนที่คุยกันไม่รู้เรื่อง

เนื้อหา:

- ผู้สร้างทำงานกับบริษัทจีนที่สร้างหนังสั้น AI
- อีกฝ่ายพูดภาษาจีน ส่วนผู้สร้างอ่านภาษาจีนไม่ออก
- บริษัทจีนส่ง `.md` เป็น Source กลาง
- ทั้ง 2 ฝั่งให้ AI อ่าน Source เดียวกัน แล้วสื่อสารเรื่องงานได้
- ผู้สร้างส่ง PDF กลับ เพราะคิดว่า PDF คือเอกสารที่ดีที่สุด
- ได้เรียนรู้ว่า PDF รักษาหน้าตาสำหรับมนุษย์ ส่วน `.md` รักษาโครงสร้างข้อความเพื่อทำงานต่อ
- หลังจากนั้นเปลี่ยน Workflow จากยัด PDF/PPT/DOC เข้า AI ทุกครั้ง เป็นใช้ไฟล์เหล่านั้นสกัด Source `.md` ก่อน
- ผลคือเร็วขึ้น พลาดน้อยลง ใช้เครดิตน้อยลง และไม่ต้องอธิบายใหม่ซ้ำ

ข้อความสรุป:

> AI ไม่ได้ต้องการเอกสารที่สวยที่สุด  
> มันต้องการ Source ที่ชัดที่สุด

กล่องอ่านเพิ่มต้องย้ำว่า AI อ่าน PDF และไฟล์อื่นได้ ไม่ใช่กฎว่า PDF เป็นภาพเสมอไป

## Phase 2 — 6 บทคือ Workflow เดียว

# SOURCE → TASTE → COOK → MULTIPLY → SEASON → SERVE

คำอธิบายสั้น:

- SOURCE — รู้ว่าเรามีอะไรและกำลังทำอะไร

- COOK — ทำ Version แรกให้เกิดขึ้น
- MULTIPLY — แตก Source เดียวเป็นหลาย Output
- SEASON — หยิบเครื่องปรุงและจัด Workflow ให้เหมาะกับงาน
- SERVE — ส่งงานออกจากแชตให้คนอื่นใช้

Cycle:

> SERVE → FEEDBACK → UPDATE SOURCE → เริ่มรอบใหม่

# 16. หลักการเรื่อง Prompt

หลักสูตรนี้ “ไม่สอนเขียน Prompt” ในความหมายว่า:

- ไม่ทำให้ผู้เรียนเชื่อว่าคำสั่งวิเศษเป็นหัวใจของงาน
- ไม่ให้จำสูตร Prompt เป็นรายเครื่องมือ
- ไม่วัดความเก่งจากการเขียนยาว
- ไม่เริ่มทุกงานจากช่องว่าง

แต่หลักสูตรยังแจก Prompt ได้ในฐานะ:

- ขวดสกัด
- เครื่องปรุง
- ฉลาก
- Recipe Card
- คำสั่งตรวจ
- คำสั่งส่งต่อ

คำประกาศ:

> เราไม่ได้ห้ามใช้ Prompt  
> เราแค่ไม่ยอมให้เครื่องปรุงแย่งบทอาหารหลัก

# 17. ทำไม Source ช่วยประหยัดเวลา เครดิต และลดความผิดพลาด

## ประหยัดเวลา

- ไม่ต้องอธิบายเป้าหมายใหม่ทุก Session
- ไม่ต้องค้นคำตัดสินใจจากแชตยาว
- ไม่ต้องบอกข้อห้ามเดิมซ้ำ
- แก้ Source จุดเดียวแล้วใช้ต่อหลาย Output
- ส่งงานให้ AI ตัวใหม่หรือคนใหม่ได้เร็ว

## ประหยัดเครดิต

- ลดการส่งไฟล์ใหญ่ซ้ำ
- ลดข้อมูลที่ไม่เกี่ยวกับงานรอบนั้น
- ลดรอบแก้จากความเข้าใจผิดพื้นฐาน
- ใช้ Source เฉพาะงานแทน Context ทุกอย่างในชีวิต

ห้ามรับประกันตัวเลขตายตัว เพราะแต่ละบริการคิดค่าใช้ต่างกัน

## ลดความผิดพลาด

- กติกาอยู่ที่เดียว
- ระบุว่าอะไรใหม่กว่าอะไร
- แยก Fact / Decision / Idea / Unknown
- มีข้อห้าม
- มี Definition of Done
- สั่งให้ถามเมื่อข้อมูลไม่พอ
- แยกสิ่งที่มาจาก Source ออกจากข้อเสนอใหม่ของ AI

## ลด AI หลอน

Source ไม่ได้ป้องกัน Hallucination 100%

มันลดพื้นที่ที่ AI ต้องเดา

คำสั่งพื้นฐานที่ติดในขวดได้:

- ใช้ Source นี้เป็นหลัก
- อย่าเติมข้อเท็จจริงที่ไม่มี
- ถ้าข้อมูลไม่พอ ให้ถาม
- ถ้าข้อมูลขัดกัน ให้ชี้ก่อน
- แยกสิ่งที่อ้างจาก Source กับข้อเสนอใหม่
- รอการยืนยันก่อนเปลี่ยนสิ่งที่ล็อกไว้

- Warm premium editorial illustration
