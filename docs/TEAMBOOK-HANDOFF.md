## ⚠️ 1. บั๊กที่ยังค้างอยู่บน production — อ่านก่อนโคลน

โคลนตอนนี้จะติดสามอย่างนี้ไปด้วย

### 1.1 กด "ลงชื่อ" แล้วไม่มีอะไรเกิดขึ้น — **มีตัวแก้แล้ว ยังไม่ได้ push**

**สาเหตุ:** commit `267cb19` เพิ่ม `JOIN xty_parties p` เข้าไปใน INSERT ของลายเซ็น
เพื่อ snapshot กิจกรรม แต่ `p` มีคอลัมน์ `head_seq` อยู่แล้ว ชนกับ `next.head_seq`
ที่มาจาก CTE → Postgres ตอบ **`42702 column reference "head_seq" is ambiguous`**

`42702` ไม่ใช่ `23505` โค้ดเลย re-throw → 500 → ปุ่มเงียบ ไม่มี error ให้ผู้ใช้เห็น

**ไฟล์:** `api/xty/[...path].js` ในฟังก์ชัน `appendPost()`

```diff
- SELECT $1,head_seq,$2,'commit',$3,$4,$5::date,FALSE,$6,$7,$8,
+ SELECT $1,next.head_seq,$2,'commit',$3,$4,$5::date,FALSE,$6,$7,$8,
```

ยืนยันแล้วกับ Postgres 16 จริง: ก่อนแก้ INSERT ล้มด้วย 42702 · หลังแก้คืน 1 แถว
และ snapshot เขียนถูกต้อง (`activity_id`, `activity_label`, `success_rule_snapshot`)

> **การแก้นี้อยู่ใน working tree ของ repo เดิม ยังไม่ได้ commit** เพราะสั่งหยุดก่อน
> ถ้าโคลนจาก main ตอนนี้ จะได้โค้ดที่**ยังพัง** — ต้องแก้บรรทัดนี้ที่ `/teambook` เอง

### 1.2 เปิดสมุดเกินลิมิตได้ — **ยังไม่ได้หาสาเหตุ**

หน้าจอผู้ใช้แสดง `4 / 2 สร้างสมุด` คือมี 4 เล่มทั้งที่เพดานคือ 2

ยังไม่ได้ไล่ ตอนที่สั่งหยุดกำลังอยู่ระหว่างตั้ง Postgres เพื่อทดสอบ

**จุดที่ควรเริ่มดู:**
- `api/_lib/xty-create-v2.js` — CTE `capacity` เป็นตัวกันโควตา ถ้า CTE คืนแถวมาทั้งที่ไม่ควร INSERT ก็ผ่าน
- `xty_party_quota_v2` — โควตานับจากตารางนี้ ไม่ได้นับจาก `xty_parties` ตรง ๆ
  ถ้าแถวโควตาหลุด/ถูก release ผิด จำนวนที่นับได้จะน้อยกว่าจริง
- `activePartyUsage()` ใน `xty/_shared/store.js` — ตัวที่หน้าเว็บใช้แสดง `4 / 2`
  ถ้าเลขนี้ถูก แปลว่า UI รู้ว่าเกิน แต่ตอนสร้างไม่ได้กัน → ปัญหาอยู่ฝั่ง server
- หน้า `/xty/new/` ไม่เตือนตอนพิมพ์ชื่อ — `syncReady()` เช็คแค่ชื่อ/กิจกรรม/ปก ไม่ได้เช็คโควตา

**ข้อควรระวัง:** ปุ่มที่กดไม่ได้เป็นแค่มารยาท ตัวที่บังคับจริงต้องอยู่ฝั่ง server เสมอ

### 2.1 Book Activity Mode — สมุดเล่มเดียวรองรับสองวิธี (`267cb19`, PR #149)

| | ทำเรื่องเดียวกัน (`shared`) | ต่างคนต่างทำ (`individual`) |
|---|---|---|
| กิจกรรม | เป็นของสมุด ทุกคน inherit | เป็นของแต่ละคน |
| ตอน join | เห็นกิจกรรมของสมุด แล้วกรอกเกณฑ์ตัวเอง (ไม่บังคับ) | เลือกสี → เลือกกิจกรรม → กรอกเกณฑ์ (บังคับ) |
| `sharedActivity*` | มีค่า | **null ทั้งหมด** |

**ไฟล์หลัก:** `xty/_shared/book-mode.js` — โมเดลกลาง ทุกหน้าจอถามผ่านตัวนี้

**กฎที่ต้องรักษาไว้ให้ได้ ถ้าย้ายไป `/teambook`:**

1. **"กิจกรรมของสมุด" ไม่มีคำตอบใน individual mode** — `bookActivity()` คืน `null`
   มีสามที่ที่เคยพิมพ์มันตรง ๆ (แถวสมุดบนชั้น · หน้ารวมสมุดสาธารณะ · ข้อความชวนเพื่อน)
   ตอนนี้ผ่าน `bookActivityLine()` ที่ตอบว่า "ต่างคนต่างทำ · แต่ละคนมีเรื่องของตัวเอง"
   **อย่าเอากิจกรรมของคนใดคนหนึ่งไปพูดแทนทั้งเล่ม**

2. **ประวัติห้ามถูกทาทับ** — วันที่ลงชื่อแล้วเก็บสำเนาของตัวเอง (activity id / label / สี / เกณฑ์)
   เขียนใน SQL statement เดียวกับที่เขียนลายเซ็น ไม่ใช่ query แยก
   วันเก่าที่ไม่มีสำเนา → รายงานว่า "ไม่รู้" (`fromSnapshot: false`) **ห้ามเติมย้อนหลังจากค่าปัจจุบัน**
   การเดาที่แต่งตัวเป็นบันทึกแย่กว่าช่องว่าง

3. **"เขียนเอง" ต้องมีสี** — เป็นใบที่ 5 ของทุกแท็บ (`custom-red`, `custom-blue`, …)
   ไม่ใช่กองที่ 17 ที่ไม่มีสี

**Schema ที่เพิ่ม** (`ADD COLUMN IF NOT EXISTS` ทั้งหมด ไม่ต้องรัน migration มือ):

```
xty_parties : activity_mode (DEFAULT 'shared') · shared_activity_description · shared_activity_color
xty_members : activity_id · activity_label · activity_description · activity_color · success_rule
xty_posts   : activity_id · activity_label · activity_color · success_rule_snapshot
```

`DEFAULT 'shared'` สำคัญ — สมุดเก่าทุกเล่มอ่านเป็น shared และทำงานเหมือนเดิม

**Activity Picker** — `xty/_shared/activity-picker.js`
4 แท็บคั่นหน้า × 5 ใบ = 20 · มือถือลงเป็น **2 + 2 + 1** · desktop 5 คอลัมน์

**ตัดขั้นตอน "สีประจำสมุด" ออก** — สมุดเป็นสีของสิ่งที่มันพูดถึง ถามสองครั้งทำให้สองค่าหลุดจากกันได้

## 3. บทเรียนที่แลกมาด้วยความเสียหายจริง

เขียนไว้เพราะแต่ละข้อทำให้เกิดความเสียหายจริงในรอบนี้ — อย่าทำซ้ำที่ `/teambook`

### 3.1 SQL ที่ไม่เคยรัน คือ SQL ที่ยังไม่รู้ว่าใช้ได้

บั๊ก 1.1 ผ่าน code review ของตัวเอง ผ่านเทสต์ 22 ข้อ ผ่าน CI เขียว ผ่าน merge
แล้วไปพังกับผู้ใช้จริง เพราะเทสต์ทั้งหมด**อ่าน SQL เป็น string** ไม่มีอันไหนรันจริง

`42702 column reference "head_seq" is ambiguous` เป็น error ที่ Postgres บอกทันที
ถ้ามีสักครั้งที่รันจริง

**ที่ควรทำ:** ตั้ง Postgres จริงแล้วรัน schema + statement จริง
ในรอบนี้ทำได้ด้วย `initdb` + `pg_ctl` ในคอนเทนเนอร์ ใช้เวลาไม่กี่นาที
เจอบั๊กภายในคำสั่งเดียว หลังจากที่ merge ไปแล้ว

### 3.2 error ที่ถูกกลืน = ปุ่มที่เงียบ

```js
catch (error) {
  if (error.code === '23505') return { error: 'ALREADY_COMMITTED', status: 409 };
  throw error;                          // ทุกอย่างที่เหลือกลายเป็น 500 เงียบ ๆ
}
```

ผู้ใช้เห็นแค่ "กดแล้วไม่มีอะไรเกิดขึ้น" ไม่มี error ให้เห็น ไม่รู้ว่าต้องรายงานอะไร
**ควรมี log ฝั่ง server และข้อความฝั่ง client สำหรับกรณีที่ไม่รู้จัก**

### 3.3 ล้างข้อมูลผู้ใช้ด้วย epoch — เคยทำข้อมูลหายมาแล้ว

`DATA_EPOCH` เคยอ่านเครื่องที่ไม่มี stamp เป็น `0` แล้วล้างข้อมูลทุกเครื่องตอน deploy

```js
if (stored === null) {                  // เครื่องที่ไม่เคยมี stamp = เครื่องเก่า
  localStorage.setItem(K_EPOCH, String(DATA_EPOCH));   // ไม่ใช่เครื่องที่พลาดการล้าง
  return;
}
```

**กฎ:** ไม่มี stamp ≠ ตกรอบการล้าง · `Number(x || 0)` กับค่าที่หายไปคือกับดัก

### 3.4 เทสต์ที่ไม่เคยถูกเรียก

`package.json` ใช้ **ลิสต์ไฟล์ที่เขียนมือ** ไม่ใช่ glob
เขียนเทสต์ใหม่สองไฟล์แล้วมันไม่เคยรันเลย จนกระทั่งไปสังเกตว่าจำนวนเทสต์ไม่เพิ่ม

**ที่ `/teambook` ควรเปลี่ยนเป็น glob** เช่น `node --test "**/*.test.mjs"`

### 3.5 พิสูจน์ว่าเทสต์ fail กับโค้ดเก่าก่อนเสมอ

ทุกเทสต์ที่เพิ่มในรอบนี้ถูก stash แล้วรันกับโค้ดก่อนแก้ เพื่อยืนยันว่ามัน fail จริง
เทสต์ที่ผ่านทั้งก่อนและหลังคือเทสต์ที่ไม่ได้ทดสอบอะไร

### 3.6 วัดในเบราว์เซอร์ อย่าอ่าน CSS แล้วเดา

- การ์ด 63:88 ที่ "ถูกแล้ว" ใน CSS วัดจริงได้ 0.7073 ควรเป็น 0.7159
- `<img width height>` + `aspect-ratio` → เบราว์เซอร์เมิน `aspect-ratio` ภาพเป็น 64×160 แทนจัตุรัส
  ต้องใส่ `height:auto`
- `justify-self:center` ทำให้ grid item หดตามเนื้อหา กรอบที่ได้ความกว้างจากภาพ
  `width:100%` อย่างเดียวจะยุบเหลือ 0

### 3.7 การ merge แบบ squash ทำให้ branch ดู "ยังไม่ merge"

commit บน branch ไม่ใช่ ancestor ของ main หลัง squash
ต้องเทียบ**เนื้อหา** (`git diff branch main`) ไม่ใช่ `git merge-base --is-ancestor`
