# Homechew v1.6 — เตรียมเปิดบ้านและติดตั้ง LINE

> พักการติดตั้งตามคำสั่งล่าสุด: ส่งเฉพาะหน้าบ้านก่อน เริ่มหลังบ้านเมื่อเริ่มผลิต โค้ด API/admin ยังอยู่ในเครื่องและไม่รวมใน commit หน้าบ้าน เอกสารด้านล่างเป็นแผนเตรียมไว้

อัปเดต 2026-09-26 · โหมดที่เจ้าของเลือก: **เก็บผู้สนใจเท่านั้น ยังไม่รับออเดอร์หรือเงิน**

เอกสารนี้เป็นสัญญาระบบปัจจุบัน เรื่องชื่อสินค้า ราคา และสถานะเปิดขายในเอกสาร v1.5 เป็นประวัติเดิมเมื่อขัดกับไฟล์นี้

## สิ่งที่เตรียมแล้ว

- หน้า `/homechew/` แสดงชื่อ **ซอสไก่ทอดหาดใหญ่ / ซอสซีฟู้ดมหาชัย / ซอสแจ่วเชียงคาน** และชุดซอสคู่บ้าน 3 รส
- ราคาเปิดตัวที่วางไว้: 159 บาท/ขวด, 399 บาท/ชุด 3 รส, ซื้อแยกรวม 477 บาท, ประหยัด 78 บาท ไม่รวมค่าส่ง ไม่มีการรับประกันวันส่งหรือขนาดบรรจุที่ยังไม่ยืนยัน
- เปลี่ยนชื่อในภาพฉลากหาดใหญ่/มหาชัยและเรนเดอร์ภาพขวดสำรองใหม่ ใช้ภาพเมืองเดิมเป็นฐาน
- คำแนะนำให้ลูกค้าเติมผักชีสดเองอยู่ในหาดใหญ่และมหาชัย เป็นคำแนะนำการเสิร์ฟ ไม่ใช่ข้อยืนยันส่วนผสมในขวด
- เอาคำบรรยาย concept ใต้ภาพรสชาติออก คงคำอธิบายสั้นเรื่องภาพประกอบไว้ท้ายหน้า เพื่อไม่ให้เข้าใจว่าเป็นภาพสินค้าจริงที่ผลิตแล้ว
- CTA ทุกจุดไป LINE เดิม `https://lin.ee/owu0J0g` เน้นรับข่าวเปิดขาย ไม่มี checkout บนเว็บ
- `/homechew/admin/`: เข้าสู่ระบบ → ผู้สนใจ → รับช่วงแชท/พักบอท/ยกเลิกรับข่าว/คำขอลบ → ออเดอร์ (เตรียมไว้) → เลือกพิมพ์ฉลากที่อยู่
- `/api/homechew?action=webhook`: ตรวจลายเซ็น LINE จาก raw bytes, ล็อกการประมวลผลรายลูกค้า, บันทึกสถานะและ event/order ใน transaction, ป้องกัน webhook ซ้ำ, ไม่ย้อนสถานะเมื่อ event เก่ามาช้า
- ผู้ช่วยมีคำตอบร้านที่กำหนดไว้ + AI แยกหัวข้อคำถามเป็นรายการที่อนุญาตเท่านั้น ไม่มีการให้โมเดลแต่งราคา/ส่วนผสม/ยืนยันเงินเอง AI ไม่ได้มีสิทธิ์สร้างออเดอร์หรือเปลี่ยนสถานะ
- ข้อความออเดอร์และชื่อ/โทรศัพท์/ที่อยู่ไม่ถูกส่งไป AI ในขั้นตอนเก็บออเดอร์ ตัวอย่าง FAQ ที่ส่งไป AI จะกรองรูปแบบโทรศัพท์/อีเมลก่อน
- ขอความยินยอมก่อนสมัครข่าว รับรสที่สนใจหลังยินยอม ยกเลิกรับข่าวได้ในแชท การเพิ่มเพื่อนอย่างเดียวไม่เท่ากับยินยอมรับข่าว
- เมื่อขอแอดมิน/ขอลบข้อมูล/ส่งภาพ/คำถามไม่ทราบ บอทส่งต่อและพักจนผู้ดูแลกดให้ตอบต่อ คำตอบสุขภาพ/ส่วนผสมไม่ยืนยันสิ่งที่ร้านยังไม่ได้ตรวจ
- ข้อมูลไม่อยู่ใน localStorage, source tree หรือไฟล์สาธารณะ ใช้ Neon PostgreSQL ฝั่งเซิร์ฟเวอร์และตาราง `hc_*` แยกจากระบบอื่น
- หลังบ้านใช้ cookie HttpOnly/Secure/SameSite=Strict อายุ 8 ชั่วโมง, ตรวจ Origin สำหรับการเปลี่ยนข้อมูล, จำกัดการลองรหัสผ่าน, ไม่มีรหัสสำรอง, ไม่คืน error ที่มีข้อมูลลับ
- หน้าแสดงสถานะการตั้งค่า LINE/AI เป็นเพียงการมี configuration **ไม่ใช่ผลทดสอบการเชื่อมจริง**

## สถานะติดตั้งจริง

ยังไม่มี credentials ของ Homechew ในงานนี้ ยังไม่เชื่อม Neon/LINE/Anthropic จริง ไม่ได้เปลี่ยนผู้ดูแลหรือ token เดิม ไม่ได้ deploy และยังไม่ผ่านการรับข้อความบน OA จริง เบราว์เซอร์ LINE Manager ต้องให้เจ้าของเข้าสู่ระบบก่อน และโดเมนเผยแพร่ต้องยืนยัน

ไฟล์ config ตัวอย่าง: `.env.homechew.example` ใช้ชื่อ `HOMECHEW_*` แยกจาก LINE Login และระบบแจ้งเตือนของสินค้าอื่นใน repo ห้ามใช้ token เดิมของระบบอื่นโดยอัตโนมัติ

## ลำดับย้าย LINE OA เดิม

1. เจ้าของเข้า [LINE Official Account Manager](https://manager.line.biz/) ด้วยบัญชีที่มีสิทธิ์ Admin และตรวจว่าบัญชีตรงกับลิงก์ร้านเดิม
2. ตรวจรายชื่อผู้ดูแลและบอกให้ชัดว่าบุคคล/ผู้ให้บริการใดเลิกใช้งานแล้ว ถอนเฉพาะสิทธิ์ที่ยืนยัน ไม่ลบประวัติแชท ผู้ติดตาม หรือบัญชี
3. ตรวจ Messaging API provider/channel, webhook URL เดิม, greeting, auto-response, rich menu และระบบภายนอกเดิม จดสถานะเพื่อสลับระบบโดยไม่ตอบซ้ำ
4. ให้เจ้าของจัดการเปลี่ยน Channel secret และเพิกถอน/ออก Channel access token ใหม่ตามชนิด token ที่ใช้อยู่ อย่าคิดว่าการออก token ใหม่จะยกเลิก token ทุกชนิดเอง และอย่าแสดง key ในแชท/เอกสาร/repo
5. สร้างฐานข้อมูล Homechew แยกหรือยืนยันฐานข้อมูลที่อนุญาต ตั้งค่าบนโฮสต์ตาม `.env.homechew.example` และตั้ง Origin ให้ตรงกับโดเมนจริง
6. Deploy เฉพาะงาน Homechew ที่ตรวจแล้ว ระวัง repo มีงานค้างอื่นจำนวนมาก ไม่ใช้ blanket add/deploy โดยไม่ตรวจขอบเขต
7. `POST https://<โดเมน>/api/homechew?action=webhook` เป็น webhook URL; raw body parser ต้องปิด (`api/homechew.js`) ตั้ง maxDuration 60 วินาทีและรวม `homechew/data/products.json` ใน function bundle
8. Verify webhook ก่อน เปิด Use webhook และ Webhook redelivery จากนั้นปิด auto-response/greeting เดิมที่ชนกับบอทใหม่ การ verify แบบ events ว่างผ่านไม่ได้แปลว่า DB/AI/แชทจริงพร้อมทั้งหมด
9. ทดสอบด้วยบัญชีเจ้าของจริง: เพิ่มเพื่อน → รับข่าว → ยินยอม → เลือกรส → ดูรายการในหลังบ้าน → ขอแอดมิน → บอทหยุด → แอดมิน resume → หยุดรับข่าว → ตรวจสถานะหลังบ้าน ใช้ลูกค้าทดสอบที่ยินยอมเท่านั้น
10. ทดสอบถาม “สั่งชุด 3 รส” ต้องตอบว่ายังไม่เปิดรับรายการ ทดสอบคำถามส่วนผสม/อายุสินค้า/แพ้อาหารต้องไม่แต่งคำตอบ
11. ตรวจชื่อธุรกิจ ช่องทางติดต่อ และการเก็บข้อมูลใน privacy page ก่อนเผยแพร่ ตรวจ noindex ของหน้าร้านให้ตรงกับแผนเผยแพร่ ส่วนหลังบ้านให้ noindex ตลอด
12. ไม่มีการส่งบรอดแคสต์ในโค้ดนี้ การประกาศเปิดขายต้องวางข้อความและกลุ่มผู้ยินยอมแยกต่างหาก ไม่ใช้ผู้ติดตามเดิมทั้งหมดเป็นกลุ่มยินยอมโดยปริยาย

การสร้าง/เปลี่ยน credentials ผ่าน browser ต้องให้เจ้าของทำขั้นตอนออกและบันทึกค่าเองตามข้อกำหนดการควบคุมเบราว์เซอร์ ไม่ส่งรหัสผ่านหรือ secret มาในแชท

## Environment

| ชื่อ | ใช้เพื่อ |
|---|---|
| `HOMECHEW_ORIGIN` | เช่น `https://www.myclover.com` ไม่มี slash ปิดท้าย ใช้ตรวจ Origin และสร้างลิงก์ข้อมูลส่วนตัว |
| `HOMECHEW_DATABASE_URL` | Neon connection string ของ Homechew ไม่มี fallback ไป DB ของโปรเจกต์อื่น |
| `HOMECHEW_LINE_CHANNEL_SECRET` | ตรวจ HMAC ของ webhook |
| `HOMECHEW_LINE_ACCESS_TOKEN` | ตอบกลับ event ของลูกค้าและอ่านชื่อโปรไฟล์ ไม่มี broadcast/push |
| `HOMECHEW_ADMIN_PASSWORD` | รหัสผู้ดูแลอย่างน้อย 16 ตัวอักษร ควรสร้างแบบสุ่ม |
| `HOMECHEW_SESSION_SECRET` | ค่าสุ่มอย่างน้อย 32 ตัวอักษร แยกจากรหัสผู้ดูแล |
| `HOMECHEW_AI_KEY`, `HOMECHEW_AI_MODEL` | Anthropic API สำหรับแยกหัวข้อ ใช้ model ID ที่บัญชีมีสิทธิ์ ไม่กำหนดรุ่นตายตัวในโค้ด |
| `HOMECHEW_ORDERS_ENABLED=0` | ปิดรับออเดอร์ ขณะนี้ `commerce_enabled` ในสินค้าเป็น false ด้วย |
| `HOMECHEW_SENDER_NAME/ADDRESS/PHONE` | ข้อมูลผู้ส่งจริงสำหรับฉลาก ป้อนฝั่งโฮสต์เท่านั้น |

ห้ามตั้ง `HOMECHEW_LOCAL=1` บน production เพราะอนุญาต cookie แบบ HTTP สำหรับ localhost ตัวแปรนี้ใช้เฉพาะ preview runner

ตรวจ configuration ด้วย `node --env-file=.env.homechew.local tests/homechew/preflight.mjs` (ใช้ไฟล์จริงในเครื่องที่ถูก gitignore ไว้): ตรวจ DB, LINE token/webhook และ AI 1 คำถาม โดยไม่ส่งข้อความให้ลูกค้า ไม่พิมพ์ secrets และไม่เปลี่ยน webhook; การเตรียม schema สร้างเฉพาะตาราง Homechew เมื่อยังไม่มี

## หลังบ้านและการดูแลข้อมูล

หน้า admin โหลดรายการหน้าละ 50 รายการ ปุ่มโหลดเพิ่มและช่องค้นหาค้นในรายการที่โหลดแล้ว รีเฟรชอัตโนมัติทุก 30 วินาทีขณะไม่แก้รายการ/เลือกพิมพ์ ข้อความที่ตอบกลับ LINE ล้มเหลวเกิน 1 นาทีแสดงเตือนเมื่อตรวจสถานะระบบ ให้ตรวจตอบจาก OA Manager; ระบบจะไม่เปลี่ยนเป็น push เองเพื่อเลี่ยงข้อความซ้ำ

ชื่อโปรไฟล์ LINE ใช้ช่วยหารายการใน OA Manager; LINE ID เป็นรหัสอ้างอิง ไม่มีลิงก์เปิดห้องแชทรายคนที่แต่งขึ้น การให้บอทตอบต่อควรทำหลังคนดูแลจบเรื่องแล้ว

ลบผู้สนใจได้เมื่อไม่มีออเดอร์เกี่ยวข้อง ถ้ามีออเดอร์ให้ตรวจข้อผูกพันการเก็บหลักฐานก่อนจัดการคำขอลบ ไม่ใช้การลบ lead เพื่อลบประวัติการขายโดยปริยาย

Cleanup เป็น lazy cleanup เมื่อมี request: events 7 วัน, rate buckets เก่า, ผู้สนใจไม่มีออเดอร์ที่ไม่ติดต่อ 180 วัน หากไม่มี request ข้อมูลจะถูกลบเมื่อมี request ถัดไป ไม่ได้ติดตั้ง cron งานนี้; ต้องแจ้งนโยบายให้ตรงการใช้งานจริง บัญชีที่มีออเดอร์และประวัติการขายยังไม่มี automatic retention ต้องกำหนดก่อนเปิดขาย

## ตอนสินค้าพร้อมเปิดรับออเดอร์

ต้องยืนยันขวด/ปริมาณจริง สูตร ส่วนผสม/สารก่อภูมิแพ้ วิธีเก็บ อายุสินค้า พื้นที่/ค่าส่ง วันที่ส่ง บัญชีรับเงิน ผู้ส่ง และ stock ก่อนเปิด โหมดตอนนี้ไม่ถือว่าได้ยืนยันข้อมูลเหล่านี้

1. ปรับหน้าร้านและคำตอบที่กล่าวว่ายังไม่เปิดขายให้ตรงกัน ตั้ง `commerce_enabled: true` และ `HOMECHEW_ORDERS_ENABLED=1` ทั้งสองจุด (เปิดแค่ env ไม่พอ)
2. เพิ่มเมนูเริ่มสั่งซื้อใน quick replies ให้เหมาะกับลูกค้า คำสั่งพื้นฐานที่เตรียมไว้: `สั่ง HC-TRIO 1`, `สั่ง HC-HY 1`, `สั่ง HC-MC 1`, `สั่ง HC-CK 1`; จำนวน 1–20 ต่อรายการ
3. เส้นทางที่ทดสอบแล้ว: เลือกสินค้า → ยินยอมเก็บข้อมูลส่งสินค้า → ชื่อ → โทรศัพท์ → ที่อยู่และรหัสไปรษณีย์ → สรุปรายการ → ยืนยันส่งรายการ → `awaiting_review`
4. ร้านตรวจ stock และค่าส่ง → `awaiting_payment` → แจ้งลูกค้าทาง OA Manager → ตรวจยอดเงินจริงและติ๊กยืนยัน → `paid` → `packing` → ใส่ขนส่ง/เลขติดตาม → `shipped`
5. การเปลี่ยนสถานะไม่ส่งข้อความออกอัตโนมัติ ทีมร้านต้องแจ้งลูกค้าทาง LINE ไม่มีระบบตรวจสลิป/ตัดสต็อก/ชำระเงิน/คืนเงินอัตโนมัติในรุ่นนี้
6. พิมพ์เฉพาะ paid/packing/shipped ต้องตั้งข้อมูลผู้ส่งก่อน เลือก thermal 100×150 มม. หรือ A4 สองฉลากต่อหน้า ปิด browser headers/footers และพิมพ์ 100% ทดลองเครื่องพิมพ์จริงก่อนใช้
7. ฉลากนี้เป็น **ฉลากชื่อ–ที่อยู่และรายการแพ็ก** ไม่ใช่ใบปะหน้าขนส่ง ไม่มีบาร์โค้ดปลอมหรือการซื้อเลข tracking ต้องเชื่อมขนส่งเพิ่มเติมหากต้องการใบปะหน้าของผู้ให้บริการ

## ตรวจในเครื่อง

ต้องใช้ Node ที่มี `node:sqlite` สำหรับ local runner (Node 22.13+; รอบนี้ Node 26.8.2) production ใช้ Neon ไม่ใช้ SQLite

```sh
node --test tests/homechew/
node tests/homechew/preview-commerce.mjs
# เปิด http://127.0.0.1:4182/homechew/admin/
# รหัสสุ่มเก็บเฉพาะเครื่อง: /tmp/homechew-commerce-local/credentials.json (permission 0600)
# sqlite และข้อมูลทดสอบอยู่ /tmp/homechew-commerce-local/ ไม่อยู่ใน repo
```

Preview runner ตอบ LINE/AI ด้วย stub เท่านั้น ไม่มีการส่งออกจริง แบบทดสอบ browser `commerce.e2e.mjs` ใช้ข้อมูลผู้รับตัวอย่าง ไม่ใช้ข้อมูลลูกค้าจริง
