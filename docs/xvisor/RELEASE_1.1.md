# X-VISOR 1.1 release integration

> Historical checkpoint. Superseded by [Story Edition 2.0](RELEASE_2.0.md);
> use the 2.0 file list, release tag and verification results for integration.

Prepared for the Front Door integration task on 10 September 2026. The user
authorized the Front Door owner to combine this release in the main commit.
The X-VISOR task does not independently commit or push the shared working tree.

## Player experience

- `/xvisor/` presents the game, existing High Scores and a start/resume button.
- `/xvisor/quest/` runs the complete 1.1 game using the player's own save.
- `/xvisor/quest/quality-preview.html`, including old scene query parameters,
  redirects to `/xvisor/quest/`. There are no scene/viewport test selectors,
  fixture imports or in-memory save replacements on the public entry.
- QA code now lives in `tests/xvisor/`; review records live in `docs/xvisor/`.
  Both are excluded from Vercel deployments. The developer scene viewer also
  restricts fixture initialization to localhost.

The release includes improved characters, sitting poses and wristbands,
graphics/motion/audio, explained Quick 3 choices, intentional month closing,
shorter meeting scenes, The Xircle completion protection, responsive Year 2
reports and actual income/growth comparison across Months 1–24. All three
income channels are visible before expanding details.

## Data continuity

Keep `SAVE_KEY = xvisorQuestContinueV4`, the existing save schema and migrations,
`SCORE_VERSION = 1.0b`, and `mc_xvisor_1b_score_sent:` markers. Display version
1.1 does not create a new leaderboard. Score initialization no longer deletes
older rows. This release requires no database reset or browser-storage cleanup.

## Verification and deployment boundary

Run `npm run test:xvisor` and the four browser scripts listed in
`../../tests/xvisor/README.md`. The loading checks explicitly exercise stale
unversioned modules, a failed dependency, retry, and preserved saves. Browser
checks use isolated contexts and do not submit real scores.

Final local results after the move and `1.1-release1` cache update:
**66/66 unit, 29/29 experience, 6/6 loading, 7/7 income layout and 11/11 player
entry checks passed**, with no uncaught browser errors. The entry check uses
real UI actions with fresh storage on desktop and mobile, then confirms that
reload, the old preview link and the landing page's resume button all preserve
the same run. Proof reports are in `/tmp/xvisor-1.1-proof/`,
`/tmp/xvisor-loading-proof/`, `/tmp/xvisor-income-layout-proof/` and
`/tmp/xvisor-player-entry-proof/`. `git diff --check` also passed.

The actual user in-app tab has been reloaded through the old preview link and
now displays `/xvisor/quest/`, rendered scenery and the normal player controls.

`.vercelignore` only governs Vercel. If another host publishes the repository
root, exclude `tests/xvisor/` and `docs/xvisor/` from its output too. There is no
Cloudflare publish-output configuration in this checkout. Do not modify only
`_redirects` for that purpose: it is generated by `tools/build.py` and both files
contain other owners' changes. The development preview's localhost guard stops
it from starting a fixture on a public host even if accidentally copied.

Earlier audit reports are historical evidence, not proof of the final live
deployment. The integrating task should report the eventual commit and push
result after its own shared-release checks.
