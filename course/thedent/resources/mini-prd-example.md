## ปัญหาและผู้ใช้

ทีมคอนเทนต์ แอดมิน และคนที่ต้องค้นข้อมูลคลินิกควรหาชื่อสาขา เบอร์ และลิงก์ติดต่อจากชุดข้อมูลเดียวกันได้ โดยมีที่มาให้ตรวจกลับ ปัญหานี้เป็นโจทย์ออกแบบสำหรับการฝึก ยังไม่ได้วัดว่าเป็นปัญหาที่เกิดบ่อยเพียงใดในทีมจริง

ผลลัพธ์: หน้าเดียวที่ช่วยค้นข้อมูลสาขาจาก Source แล้วคัดลอกเบอร์หรือดูช่องทางติดต่อได้ โดยไม่ต้องให้ AI สร้างคำตอบใหม่ทุกครั้ง

## ขอบเขตต้นแบบ

branch-desk.html เป็นไฟล์เดียวพร้อม CSS/JavaScript ในตัว เปิดจากเครื่องโดยไม่ติดตั้งและไม่ดึงไลบรารีภายนอก ข้อมูลที่ใช้แสดงอยู่ในไฟล์และสืบกลับไปที่ Source ได้

หน้าจอมีหัวเรื่อง คำอธิบายขอบเขต ช่องค้นหา ปุ่มล้างคำค้น การ์ดข้อมูล ปุ่มคัดลอกข้อมูลติดต่อ ลิงก์โทร/LINE/เว็บไซต์/ต้นทาง วันที่ตรวจ และหมายเหตุรอยืนยันจำนวนสาขา รองรับมือถือ

ค้นจากชื่อสาขาและจุดสังเกต ไม่ใช้ชื่อบริการเป็นหลักฐานว่าบริการนั้นมีในทุกสาขา ปุ่มคัดลอกแจ้งผลตามจริงและให้เลือกคัดลอกเบอร์เองได้เมื่อสิทธิ์ clipboard ไม่พร้อม

ไม่สร้างระบบจอง ไม่ยืนยันคิว ไม่แต่งเวลาทำการ ราคา หรือผลการรักษา ไม่มีข้อมูลผู้ป่วย และไม่เชื่อม ERP การเลือกสาขาไม่มีผลต่อระบบคลินิก

## ลำดับการใช้งาน

เปิดไฟล์ → ค้นชื่อสาขา → อ่านชื่อ/จุดสังเกต/เบอร์ → คัดลอกข้อมูลติดต่อหรือเลือกช่องทาง → ตรวจ URL ต้นทางเมื่อข้อมูลต้องยืนยัน

การเปิดลิงก์เกิดจากผู้ใช้เลือกเองเท่านั้น ตัวต้นแบบไม่โทร ไม่ส่งข้อความ และไม่ส่งคำขอจองอัตโนมัติ

## ข้อมูลและการตัดสินใจที่ยังเปิดอยู่

- O01: จำนวนสาขาที่เปิดล่าสุด ต้องให้ผู้รับผิดชอบคลินิกยืนยันพร้อมวันที่มีผล
- O02–O05: เวลาทำการ บริการ/คิว ราคา และขั้นตอนยืนยันนัด ยังไม่ใช้เป็นข้อเท็จจริงในต้นแบบ
- O06–O08: ช่องทางหลักที่ทีมจะดูแล โปรไฟล์ปลายทาง และน้ำเสียงที่อนุมัติ ยังต้องถามเจ้าของข้อมูล
- ต้องเลือกเจ้าของ Source และผู้ตรวจชื่อ–เบอร์–URL ก่อนนำไปใช้ต่อในทีม
