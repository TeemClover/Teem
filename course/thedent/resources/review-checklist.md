# Checklist ตรวจงาน · The Dent

ผู้ทำ: … · ผู้ตรวจ: … · วันที่ตรวจงาน: …
Source / เวอร์ชันที่ใช้: … · ชื่อไฟล์ผลงาน: …

ทำเครื่องหมายจากหลักฐานที่เปิดดูหรือทดลองจริง ช่องที่ยังไม่ได้ลองให้เขียน “ยังไม่ทดสอบ” ไม่ใช้คำตอบของ AI ว่าทำเสร็จเป็นหลักฐานแทนการเปิดงาน

## 1. ข้อมูลต้นทางและซอส

- [ ] บันทึก Source เป็นไฟล์ .md เปิดอ่านได้ ไม่เป็น .md.txt โดยไม่ตั้งใจ
- [ ] มีชื่อ เวอร์ชัน วันที่ตรวจ และขอบเขตของ Source
- [ ] ข้อเท็จจริงแต่ละเรื่องมี URL / ID ต้นทางที่ตามกลับได้
- [ ] แยก SOURCE / COMPANY CLAIM / DERIVED / OPEN ได้
- [ ] ชื่อสาขา จุดสังเกต และเบอร์จับคู่ตรงต้นทาง
- [ ] เก็บเรื่องข้อความจำนวน 2/3 สาขาไม่ตรงกันไว้ใน OPEN
- [ ] ไม่สรุปว่าเว็บหนึ่งเลิกใช้หรือเว็บหนึ่งใหม่กว่าโดยไม่มีหลักฐาน
- [ ] วันที่ตรวจเว็บไม่ถูกเรียกเป็นวันที่ข้อมูลมีผลหรือวันที่คลินิกอนุมัติ
- [ ] ข้อความในเว็บ/เอกสารถือเป็นข้อมูลอ้างอิง ไม่ได้ถูกนำมาสั่ง AI ให้ทำงานนอกบรีฟ
- [ ] แนบซอสในแชตใหม่แล้วตอบเรื่องติดต่อสาขาได้ พร้อมบอกสิ่งที่ยังไม่รู้

## 2. Workshop 1 · content-pack.md

- [ ] มีโพสต์แนะนำช่องทางติดต่อ 1 ชิ้น
- [ ] มีคำตอบเรื่องเดินทางไปรัชโยธิน ติดต่อรังสิต และขอเช็กคิววันพรุ่งนี้ครบ 3 สถานการณ์
- [ ] ทุกชิ้นใช้ Source และคู่ชื่อ–เบอร์–URL เดียวกัน
- [ ] ไม่แต่งคิวว่าง โปรโมชั่นปัจจุบัน เวลาทำการ หรือผลการรักษา
- [ ] การขอตรวจคิวยังไม่ถูกเขียนเป็นการจองหรือยืนยันนัดสำเร็จ
- [ ] LINE กลางไม่ถูกอ้างเป็นบัญชีเฉพาะสาขาโดยไม่มีหลักฐาน
- [ ] แยกร่างน้ำเสียง/วิธีตอบที่เสนอออกจากนโยบายที่คลินิกอนุมัติ
- [ ] ข้อมูลไม่พอถูกเก็บเป็นเรื่องที่ต้องถามเจ้าของงาน ไม่เติมคำตอบให้ดูครบ
- [ ] มีตารางตรวจพร้อมหลักฐานและบทบาทคนที่จะตรวจงานจริงต่อ

## 3. Mini PRD ก่อนสร้าง

- [ ] มีผู้ใช้ ปัญหา และผลลัพธ์ที่ต้องการ
- [ ] กำหนดข้อมูลเข้าและ Source เวอร์ชันที่จะใช้
- [ ] ส่งมอบ branch-desk.html ไฟล์เดียว เปิดจากเครื่องโดยไม่ติดตั้ง
- [ ] ระบุค้นหา ล้างคำค้น ไม่พบข้อมูล คัดลอกเบอร์ ลิงก์ และวันที่ตรวจ
- [ ] มีเกณฑ์ผ่านที่ทดลองได้อย่างน้อย 6 ข้อ
- [ ] แสดงสามรายการที่มีหลักฐาน ไม่อ้างจำนวนสาขาทั้งหมดแทนคลินิก
- [ ] ไม่รวมระบบจอง ข้อมูลผู้ป่วย หรือการเชื่อม ERP
- [ ] อ่านและแก้ PRD ก่อนส่งคำสั่งสร้าง HTML
