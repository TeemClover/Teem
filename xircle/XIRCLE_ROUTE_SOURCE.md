## 1. Xircle Route นี้คืออะไร

Xircle Route บน myClover คือ **Experience + Education + Interpretation + Activation Layer**

หน้าที่ของมันไม่ใช่สร้าง Health Tracker อีกตัว แต่ทำให้คนเดินจาก:

**เห็นข้อมูล → เข้าใจชีวิตจริง → เลือกสิ่งที่จะทำ → วางให้ทำซ้ำ → ทำด้วยกัน → กลับมาทบทวน**

เส้นหลักคือ:

**Xircle → Human Care → X-VISOR → RoutineX → สมุดแมวขาว / White Cat Care → กลับมาทบทวน Xircle**

แนวคิดสำคัญ:

- ข้อมูลช่วยให้เรา **เห็น**
- คนช่วยเติม **บริบท**
- RoutineX ช่วยวางสิ่งที่เลือกให้ **ทำซ้ำได้**
- สมุดแมวขาวช่วยให้คน **ทำด้วยกันและกลับมาได้**
- Xircle กลับมาช่วย **ทบทวนสิ่งที่เกิดขึ้นจริง**

นี่คือวงเดียวกัน แต่แต่ละส่วนมีงานของตัวเอง

## 2. สิ่งที่ Route นี้ไม่ใช่

Route นี้ **ไม่ใช่ Xircle App เวอร์ชันเว็บ** และไม่ควรพยายามเป็น

ไม่ควรสร้างซ้ำสิ่งเหล่านี้ใน Route:

- ระบบเก็บข้อมูลสุขภาพจริงแบบ App
- device pairing / Band / Scale runtime
- food logging engine จริง
- live steps / workout / sleep engine
- Body Composition engine
- Habit Score production engine
- trend dashboard จริง
- medical interpretation หรือ diagnosis

สิ่งที่ทำบนเว็บไซต์ได้คือ **จำลองให้เข้าใจ, สอนวิธีอ่าน, ทำให้เห็นความสัมพันธ์ และพาไปสู่การลงมือ**

## 3. Xircle App ของบริษัททำอะไร

Xircle App มี positioning เป็น **The Habit Tracker**

แกนหลักของ App:

- Eat
- Move
- Sleep
- Habit Score
- Band / Scale
- Body Composition
- Bio Age / MaxAge™
- Daily feedback / trend

หลักสำคัญของ App คือ:

**Understand Yesterday. Adjust Today.**

Habit Score ใช้ **Eat + Move + Sleep เท่านั้น**

Body Composition เป็น Outcome Layer ที่แยกจาก Habit Score โดยตั้งใจ ไม่ใช่วงที่ 4 ของ Habit Score

ดังนั้น App ตอบคำถามประเภท:

- กิน / ขยับ / นอน เป็นอย่างไร?
- แนวโน้มร่างกายตอบอย่างไร?
- วันนี้มีข้อมูลอะไรให้ปรับ?

## 4. ทำไม Website Route ไม่ซ้ำกับ Xircle App

### Xircle App = เครื่องมือใช้งานจริง

App เก็บและแสดงข้อมูลจากชีวิตจริง

**Measure → Record → Score → Trend → Feedback**

### Xircle Route = ทำให้คนเข้าใจว่าจะใช้ข้อมูลนั้นยังไง

Website Route ทำหน้าที่:

**Experience → Understand → Interpret → Choose → Repeat → Care → Together**

ตัวอย่าง:

- App บอกว่า Sleep ลดลง
- Route สอนว่า “Sleep ลดลง” ยังไม่บอกว่าเพราะอะไร
- Human Care / X-VISOR พาไปถามบริบท
- RoutineX พาเลือกสิ่งเดียวแล้ววางให้ทำซ้ำ
- สมุดแมวขาวช่วยถือจังหวะให้กลุ่มกลับมาคุยและทำต่อ
- จากนั้นกลับไปดูข้อมูลจริงใน Xircle อีกครั้ง

ดังนั้น Route ควร **เพิ่มคุณค่าให้ App** ไม่ใช่แย่งงาน App

### กฎสำหรับงานใหม่

ถ้าฟีเจอร์ใหม่ตอบว่า **“เก็บ/คำนวณข้อมูลสุขภาพจริง”** → ควรเป็นงานของ Xircle App

ถ้าฟีเจอร์ใหม่ตอบว่า **“ช่วยให้คนเข้าใจข้อมูล, ตัดสินใจ, เรียนรู้, ฝึก, วาง Routine, หรือทำต่อกับคนอื่น”** → เหมาะกับ Xircle Route บน myClover

### หน้าที่

1. ความจำของคนไม่ครบทุกชิ้น
2. เก็บ Sleep
3. เก็บ Eat
4. เก็บ Move
5. เช้าวันถัดไปเห็นภาพของเมื่อวาน
6. Eat + Move + Sleep กลายเป็น Habit Score
7. วันนี้เลือกแค่ 1 อย่าง
8. เห็นข้อมูลไม่ได้แปลว่าจะทำได้ทุกวัน
9. แสดง Connected Loop ของระบบ
10. พาเข้า Human Care

### Habit Score UI

- 3 concentric rings
- Eat / Move / Sleep
- เลขคะแนนอยู่กลางวง
- คำว่า `Habit Score` อยู่ฝั่งคำอธิบาย ไม่ควรจมอยู่ในวง

### สิ่งที่ผู้ใช้ควรเข้าใจเมื่อจบหน้า

> “ข้อมูลทำให้ฉันเห็นเมื่อวาน แต่ก่อนจะเลือกว่าจะทำอะไรต่อ ฉันยังต้องเข้าใจชีวิตจริงของคนก่อน”

## 5.2 `/xircle/care/` — Human Care

### หน้าที่

สร้างสะพานจาก “ข้อมูล” ไปสู่ “คน”

### Key message

**ข้อมูลช่วยให้เราเห็น คนช่วยให้เราไปต่อ**

Xircle เห็น Pattern แต่ข้อมูลไม่ได้เห็นทั้งชีวิต

ตัวอย่าง:

- ข้อมูลเห็น Sleep ลดลง
- แต่ไม่รู้ว่าคนคนนั้นต้องตื่นดูแลลูกหลายคืน

### บทบาทของ Human Care

- ถามเป้าหมาย
- ฟังบริบท
- เลือก 1 อย่าง
- ติดตาม
- รู้ขอบเขต

Human Care ไม่ได้มีไว้ให้คน “อ่านเลขเก่ง” อย่างเดียว แต่ทำให้ข้อมูลกลายเป็นสิ่งที่ช่วยชีวิตจริงได้

## 5.3 `/xircle/opportunity/` — X-VISOR Simulator

### หน้าที่

ให้คน “ลองคิดแบบ X-VISOR” ก่อนอ่านทฤษฎี

### Flow

1. **เห็นสัญญาณ** — ข้อมูลเปลี่ยน แต่ยังไม่ตีความทันที
2. **เข้าใจบริบท** — ถามว่าเกิดอะไรขึ้นในชีวิตจริง
3. **เลือก** — เลือกสิ่งเล็กที่ทำได้จริง
4. **ติดตาม** — ถามว่าติดตรงไหน ไม่ใช่ตรวจการบ้าน
5. **รู้ขอบเขต** — ไม่วินิจฉัย และรู้ว่าเมื่อไรควรส่งต่อ
6. **สรุปวิธีคิด**

### Formula ที่คนควรจำ

**เห็น → ฟัง → เลือก → ติดตาม → รู้ขอบเขต**

### Guardrail

Simulator เป็นสถานการณ์สมมติ

- ไม่ใช่การวินิจฉัย
- เล่นจบไม่ได้แปลว่าสอบผ่าน X-VISOR
- การวินิจฉัยต้องเป็นหน้าที่ของผู้เชี่ยวชาญด้านสุขภาพ

### ไปต่อ

`/xircle/routinex/`

คำถามที่ใช้เป็น bridge:

> “เลือกสิ่งที่จะทำต่อได้แล้ว แล้วจะทำให้มันเกิดซ้ำทุกวันยังไง?”

# 6. RoutineX Route

## `/xircle/routinex/`

### หน้าที่

พาคนจาก “รู้ว่าจะทำอะไร” ไปสู่ “วางให้เกิดซ้ำในชีวิตจริง”

RoutineX ไม่ควรเปิดด้วยสินค้า

ต้องอธิบายก่อนว่า:

- อะไรต้องลงมือเอง
- อะไรมีตัวช่วยได้
- ตัวช่วยไม่แทนพฤติกรรม

### Canonical structure

**ABCD + Flavor+**

ไม่มี E

ห้ามเปลี่ยนเป็น ABCDEF

---

## 6.1 A · ABSORB

หน้าที่: วางเรื่องการกิน/การย่อยให้อยู่ใน Routine

ตัวช่วยในส่วนนี้:

- G.U.S.+

---

## 6.2 B · BUILD

หน้าที่: ให้สิ่งที่ทำซ้ำมีโภชนาการรองรับ

ตัวช่วยในส่วนนี้:

- Protein HMB+

ไม่ใช้ผลิตภัณฑ์แทนอาหารหรือพฤติกรรม

---

## 6.3 C · CONTROL

**ส่วนนี้ไม่มีขาย**

C คือหัวใจของ RoutineX:

- การเลือก
- การลงมือ
- ความรู้
- พฤติกรรม

ระบบช่วยเตือน, ช่วยวาง, ช่วยติดตามได้ แต่ไม่มีสินค้าไหนลงมือแทนคนได้

นี่คือแกนสำคัญที่สุดในการทำให้ RoutineX ไม่กลายเป็นหน้าขายสินค้าอย่างเดียว

---

## 6.4 D · DAILY BALANCE

หน้าที่: ชั้นตัวช่วยสำหรับวันจริงที่ไม่ได้สมบูรณ์ทุกวัน

ตัวช่วย:

- Vita Matrix
- AstaMega+

ห้ามสื่อว่า “ทุกคนขาด” หรือ “ทุกคนต้องใช้”

---

## 6.5 Flavor+

หน้าที่: ลดความจำเจเพื่อช่วยให้ Routine ทำต่อได้ง่ายขึ้น

ไม่ใช่การรับประกันผลลัพธ์

---

## 6.6 RoutineX System Summary

หลัง A / B / C / D / Flavor+ ต้องมีหน้าสรุประบบก่อนขายสินค้า

ข้อความแกน:

> A / B / D และ Flavor+ คือชั้นของตัวช่วย ส่วน C คือพฤติกรรมที่คนลงมือเอง

Loop:

**เลือก → ทำ → มีตัวช่วย → ทำซ้ำ → กลับมาดูแล้วปรับ**

Diagram ใช้ motion เพื่อสื่อ connection และ loop ไม่ใช่แค่เปลี่ยนสี node

## 8.1 `/xircle/circle/` — อธิบายสมุดแมวขาว 28 วัน

### หน้าที่

ขายความเข้าใจก่อนเปิดสมุดจริง

Key message:

**ทำทีละนิด แต่ไม่หายไปจากกัน**

สมุดไม่ได้มีไว้เฝ้ากันทั้งวัน แต่ช่วยถือจังหวะให้กลุ่มกลับมาคุยและทำต่อ

### Checkpoints

- Day 0 — เลือก 1 อย่าง
- Day 3 — เช็กว่าไหวไหม
- Day 7 — ดูด้วยกัน
- Day 14 — ปรับ 1 อย่าง
- Day 21 — รักษาจังหวะ
- Day 28 — ทบทวนแล้วเลือกต่อ

28 วันคือ **care / coaching cadence** ไม่ใช่ deadline ทางสรีรวิทยา

### Circle simulation

หน้าแสดงตัวอย่างว่า:

- ใครกลับมาแล้ววันนี้
- ไม่มี leaderboard
- ไม่มีคะแนนแข่งขัน
- วันที่ไม่ครบไม่ใช่ความล้มเหลว
- ไม่มีข้อมูลสุขภาพของสมาชิกถูกแชร์อัตโนมัติ

### Conversion

- เปิดสมุดใหม่
- หรือเข้าร่วมสมุดเดิมด้วยรหัส

# 13. ทำไม Route นี้ดีกับการใช้ RoutineX

## 13.1 คนเข้าใจ C ก่อนสินค้า

---

## 13.2 RoutineX มีเหตุผลจากข้อมูลจริง

Xircle เริ่มจากเมื่อวาน

คนไม่ได้เลือก Routine จากความรู้สึกลอย ๆ แต่เริ่มจากสิ่งที่เห็นใน Eat / Move / Sleep แล้วเลือก 1 อย่าง

---

## 13.3 X-VISOR เติมสิ่งที่ข้อมูลไม่รู้

ข้อมูลอย่างเดียวอาจชี้ผิดทิศถ้าไม่รู้บริบท

Human Care + X-VISOR ช่วยกันกรองว่าอะไร “เหมาะกับชีวิตจริง” ก่อนวาง Routine

---

## 13.4 28 วันทำให้ Routine ไม่จบที่การซื้อ

สมุดแมวขาวทำให้ RoutineX มี follow-up layer:

- ตกลงกัน
- เช็กอิน
- ปรับ
- กลับมา
- ทำต่อ

นี่ช่วยให้ “การใช้ RoutineX” กลายเป็น process ไม่ใช่ transaction

---

## 13.5 กลับไปหา Xircle ได้

Loop ไม่จบที่ Day 28

ผู้ใช้สามารถกลับไปดู Xircle แล้วถามว่า:

- Pattern เปลี่ยนไหม?
- สิ่งที่เลือกทำได้จริงไหม?
- ควรปรับอะไรต่อ?

จึงเกิด continuous feedback loop

# 14. ทำไม Route นี้ดีกับธุรกิจ

## 14.1 สร้างความต้องการก่อนขาย

คนเห็นปัญหาและเข้าใจโครงก่อนถึง product window

สินค้าจึงปรากฏในฐานะ “ตัวช่วยที่มีตำแหน่งใน Routine” ไม่ใช่ของที่ถูกยัดขาย

---

## 14.2 เพิ่มคุณภาพของคนที่สนใจสินค้า

คนที่กดดูสินค้าใน RoutineX ผ่านมาแล้วว่า:

- ข้อมูลคืออะไร
- บริบทสำคัญยังไง
- C ไม่มีขาย
- ตัวช่วยแต่ละชั้นทำงานตรงไหน

จึงเป็น intent ที่มีบริบทมากกว่าการเห็น product card ตรง ๆ

---

## 14.3 ลดภาระการอธิบายของคนขาย/คนดูแล

Route ทำหน้าที่อธิบาย framework ซ้ำ ๆ ให้เป็นระบบ

ทีมไม่ต้องเริ่มจากศูนย์ทุกครั้ง

คนสามารถกลับไปอ่านเองได้

---

## 14.4 ทำให้ X-VISOR มีบทบาทจริง

แทนที่จะขายด้วย product knowledge อย่างเดียว Route ทำให้ Human Care เป็นส่วนหนึ่งของ customer journey

นี่ช่วยสร้างความแตกต่างของ ecosystem:

**Data + Human Care + Routine + Together**

---

## 14.5 เพิ่ม retention โดยไม่ใช้แรงกดดัน

สมุดแมวขาวออกแบบให้คนกลับมาเป็นจังหวะ ไม่ใช่ถูกตามทุกวัน

แนวทางนี้ช่วยให้ relationship หลังการซื้อมีเหตุผลที่เป็นประโยชน์กับผู้ใช้จริง

---

## 14.6 เปิดพื้นที่ขายหลายระดับโดยไม่ทำลาย Journey

- ใช้ Route ฟรีเพื่อเข้าใจ
- อ่านข้อมูลเชิงลึก
- ดูสินค้า RoutineX
- เปิดสมุดแมวขาว
- เรียน/ฝึก X-VISOR
- กลับมาใช้ Xircle ต่อ

ไม่จำเป็นต้องบังคับทุกคนเข้าทางเดียว

# 16. Visual / Interaction Rules ที่ต้องรักษา

## Mobile

- ภาพเป็นพระเอก

- ภาพที่มี baked UI/text สำคัญต้องอ่านครบ
- CTA หลักต้องอยู่ตำแหน่งคงที่ แม้ข้อความตอบกลับยาวไม่เท่ากัน
- controls ต้องกดได้ทันที ไม่ต้องรอ narration

## RoutineX

- diagram และ copy ห้ามทับกัน
- diagram ต้องเห็น node ครบ ไม่แหว่ง
- animation ใช้สื่อ connection / loop
- final product hero fit ตามสัดส่วนภาพจริง ไม่ต้องใช้กรอบสูงเท่า diagram

## Copy

- Thai-first
- ชื่อระบบอังกฤษใช้ได้เมื่อเป็นชื่อจริง
- อย่าใช้ศัพท์เทคนิคถ้าไม่จำเป็น
- คนต้องอ่านทุกบรรทัดที่อยู่ใน Journey หลักได้
- technical/source detail → ย้ายไปข้อมูลเชิงลึก

# 20. คำอธิบาย Route สำหรับใช้กับคนนอก

# 22. คำสั่งเริ่มต้นสำหรับ AI ตัวใหม่
