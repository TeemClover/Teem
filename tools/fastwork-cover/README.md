## ข้อเท็จจริงเรื่องปก Fastwork

ตรวจจากโค้ดและ CSS ของหน้า https://fastwork.com/user/teem ที่เสิร์ฟจริงเมื่อ 2026-11-12 (อ่านอย่างเดียว ไม่ได้ล็อกอิน)

**ยืนยันแล้ว (จากโค้ดหน้าเว็บ)**

- ปกรองรับ 3 แบบ: `video`, `image` และภาพหลายใบ (สไลด์โชว์ สลับทุก 4 วินาที)
- ปกวิดีโอถูกวาดเป็น `<video class="media" autoplay loop playsinline>` และตั้ง `muted` — เล่นวนเองโดยไม่มีปุ่มควบคุม
- ข้อความในหน้าต่างเพิ่มปก: "อัปโหลดวิดีโอ หรือโชว์โพสต์เด่น ขนาด: 1920 × 1080 px"
- ตัวอัปโหลดฝั่งเบราว์เซอร์รับวิดีโอ MP4 / MOV / M4V / WebM ไม่เกิน 1.5 GB และรูป JPG / PNG / WebP / GIF / HEIC ไม่เกิน 20 MB
- ปกวิดีโอมีเมนู "เปลี่ยนภาพตัวอย่าง — เลือกเฟรมหรืออัปโหลดรูป"
- สื่อในช่องปกใช้ `object-fit: cover` กึ่งกลางเสมอ และช่องปกมี 3 ขนาดตามความกว้างของหน้าโปรไฟล์:

| ความกว้างหน้าโปรไฟล์ | ช่องปก | สิ่งที่ทับปก |
| --- | --- | --- |
| ≥ 960px (desktop) | 16:9 กว้างสุด 680px มุมโค้ง 18px (วัดได้ 674×379 ที่จอ 1440) | ไม่มี |
| 768–959px | 21:9 เต็มความกว้าง | รูปโปรไฟล์ 80px ทับมุมล่างซ้าย 48px |
| < 768px (มือถือ และแท็บเล็ตแนวตั้งถึงราว 840px) | **สูงคงที่ 200px** เต็มความกว้าง | แผงข้อมูลสีขาวทับ 36px ล่าง (มุมโค้ง 24px) · รูปโปรไฟล์ 72px ที่ซ้าย 16px เริ่มที่ 128px จากขอบบนปก · มุมมองเจ้าของมีปุ่มเมนู 40px (ซ้ายบน) และปุ่ม Preview 107×40 (ขวาบน) ห่างขอบ 16px/8px |

**ยังไม่ได้ยืนยัน (ต้องล็อกอินอัปโหลดจริงจึงรู้)**

- ขั้นตอนอัปโหลดและการแปลงไฟล์ฝั่งเซิร์ฟเวอร์ (ความละเอียด/บิตเรตที่ Fastwork เสิร์ฟจริง, จำกัดความยาวหรือไม่)
- ภาพตัวอย่างที่ระบบเลือกให้อัตโนมัติ และสิ่งที่แสดงเมื่อเบราว์เซอร์ของผู้ชมไม่ยอม autoplay (เช่น โหมดประหยัดพลังงานของ iPhone)
- มุมมองผู้ชมที่ล็อกอินบนมือถือมีปุ่มทับปกแบบเดียวกับเจ้าของหรือไม่ (ออกแบบเผื่อไว้แล้ว: มุมบนซ้าย/ขวาไม่มีสารสำคัญ)

## Safe area — ทำไมปกเดิมถูกตัด และปกนี้แก้อย่างไร

ปกเดิม 2000×500 (4:1) ถูก `object-fit: cover` ตัดด้านข้าง: บน desktop (16:9) เหลือความกว้างที่เห็น 44% และบนมือถือ 390px เหลือ 49% ชื่อจึงหลุดจอ
ปกนี้ทำที่ **1920×1080** ตามที่ Fastwork ระบุ ทำให้ desktop เห็นทั้งเฟรม และมือถือกว้าง ≥ 356px **ไม่ถูกตัดด้านข้างเลย** เหลือเฉพาะการตัดบน/ล่าง ซึ่งคุมด้วยการแบ่งเฟรมเป็นสองชั้น:

| ชั้น | อยู่ตรงไหนของเฟรม 1920×1080 | เหตุผล |
| --- | --- | --- |
| สารหลัก (ชื่อ · ใจความ · บริการ) | y 352–592, x 112–754 | อยู่ในแถบที่ทุกขนาดจอเห็นร่วมกัน: จอ 390px เห็น y 48–853, จอ 430px เห็น y 94–826, แท็บเล็ต 820px เห็น y 306–690 อยู่เหนือรูปโปรไฟล์ (เริ่ม y 677 / 665 / 605 ตามลำดับ) และต่ำกว่าปุ่มเมนูของมุมมองเจ้าของบนจอ 428px (สิ้นสุด y 307) |
| ชิ้นงานหลัก | y 255–800 ทางขวา | เห็นครบบนมือถือ ถูกตัดขอบบน/ล่างเล็กน้อยบนแท็บเล็ตโดยไม่เสียความหมาย |
| บรรยากาศ | พื้น เงาสะท้อน แสง ด้านบน/ล่างและขอบขวา | ถูกครอปหรือถูกแผงข้อมูลทับได้ |

## ดูตัวอย่างและเรนเดอร์ใหม่

ต้องมี Node 20+, Playwright (Chromium) และ ffmpeg

```bash
# ดูสดในเบราว์เซอร์ (เล่นวนตามเวลาจริง)
python3 -m http.server 4173        # จาก root ของ repo แล้วเปิด http://localhost:4173/tools/fastwork-cover/
#   ?still=1   องค์ประกอบของปกภาพนิ่ง        ?guides=1   เส้นครอปของ Fastwork        ?t=5.9   หยุดที่เวลานั้น

node tools/fastwork-cover/render.mjs            # master + ไฟล์ Fastwork + ภาพนิ่ง + loop-report (ราว 5 นาทีบนเครื่อง 4 คอร์)
node tools/fastwork-cover/render.mjs --draft    # 960×540 ดูเร็ว
node tools/fastwork-cover/render.mjs --stills   # เฉพาะภาพนิ่ง
node tools/fastwork-cover/frame.mjs /tmp/f.png 5.9            # เฟรมเดียวที่เวลา 5.9 วินาที
node tools/fastwork-cover/mockup.mjs                          # ภาพจำลองมุมมองเจ้าของ + crop map
node tools/fastwork-cover/fastwork-live-check.mjs [ไฟล์]      # ใส่ไฟล์ในช่องปกของหน้า Fastwork จริง (เฉพาะในเบราว์เซอร์ทดสอบ ไม่อัปโหลด)
```

แก้ข้อความ: `index.html` · แก้สี/ตัวอักษร: `cover.css` · แก้จังหวะ: ค่า `K` ต้นไฟล์ `cover.js` · เปลี่ยนชิ้นงาน: `PIECES` ใน `cover.js`
ทุกเฟรมคำนวณจากเวลา (`window.__cover.seek(t)`) จึงเรนเดอร์ซ้ำได้ผลเดิมทุกครั้ง

## วิธีอัปโหลด

1. เปิดโปรไฟล์ → แตะปก → "เปลี่ยนภาพปก" → เลือก **วิดีโอ** → อัปโหลด `teem-clover-cover-fastwork-1080p30.mp4`
2. ถ้าระบบให้เลือกภาพตัวอย่าง เลือกเฟรมแรก หรืออัปโหลด `teem-clover-cover-first-frame.jpg`
3. ตรวจบนมือถือจริงและ desktop ว่าเล่นวน และชื่อไม่ถูกตัด ถ้าวิดีโอไม่ผ่าน ใช้ `teem-clover-cover-static-1920x1080.jpg` แบบ "รูปภาพ" แทน
