# Clover Compendium

Compendium is institutional memory, not a marketing page.

## Start here

Read:

1. `compendium/README.md`
2. Latest closed file in `compendium/months/`
3. `compendium/SKILLS.md` when the task involves strategy, prioritization, CEO development, experiments, distribution, sales, or content.

If the current task directly relates to an older month, read that month too.

## How to use the memory

Treat entries as three different evidence classes:

- **Observed fact:** happened, shipped, cost, measured, or directly observed.
- **Interpretation / lesson:** current explanation derived from facts; useful but revisable.
- **Hypothesis:** must still be tested; never state as proven merely because it appears in Compendium.

Do not silently revive a closed assumption. If new evidence suggests an old decision should change, state the new evidence and update the next monthly close.

## Before proposing substantial work

For work likely to consume meaningful founder time, credits, budget, or scope, answer internally:

1. What user behavior or business outcome is this supposed to change?
2. What evidence says this is the current bottleneck?
3. What is the cheapest meaningful test?
4. Does Compendium contain a lesson warning against this pattern?
5. What signal would make us stop, continue, or scale?

Do not use code, premium video, polish, or a new destination as the default solution to a distribution or demand problem.

## Monthly close procedure

Create `compendium/months/YYYY-MM.md` with:

- executive snapshot;
- major workstreams;
- material money/time/resource costs;
- what worked;
- what failed or surprised us;
- decisions made;
- CEO operating feedback;
- observed facts vs interpretations vs open hypotheses;
- skills gained / skill gaps;
- rules extracted for future agents;
- next-month priorities;
- stop-doing list.

Then update `compendium/SKILLS.md` only when evidence warrants a level or mission change.

## Skill leveling rule

A level is earned by repeated evidence or a newly demonstrated operating capability, not by effort, confidence, number of features, or visual polish.

For weak/bottleneck skills, attach a measurable next mission. For strong skills, actively note the danger of overuse.

## August 2026 anchor lesson

August established a major constraint: building and premium AI-production capability were ahead of distribution capability. Higgsfield direct spend was approximately USD 1,140 while resulting TeamBook/RoutineX videos did not create meaningful distribution. Expensive video must therefore be treated primarily as a production multiplier after cheap idea/hook validation, not as the default experiment lab.

When future work touches AI video, distribution, TeamBook feature scope, RoutineX content, or new front doors, read `compendium/months/2026-08.md` first.
