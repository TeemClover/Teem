# เริ่มตรงนี้ — Lucky Source by myClover

**ไม่ต้องเขียนโค้ดเอง เริ่มจากบ้านที่คุณอยากทำ**

1. แตก ZIP แล้วใส่แปลนใน `MY-HOUSE/plans/` ภาพใน `MY-HOUSE/photos/` ถ้ามีโดรนให้ใส่ `MY-HOUSE/aerial/`
2. เปิด Work เลือก GPT Astra 6.0 ตามชื่อที่มีในบัญชีของคุณ ให้สิทธิ์อ่านโฟลเดอร์นี้และสร้างงานใน `OUTPUT/` ผ่านหน้าจออนุญาตของแอป หรือแนบ ZIP กับไฟล์บ้านให้แชตจริง ๆ
3. ส่งข้อความใน `01-START-PROMPT.txt` แล้วให้ AI ลงมือเปิดบ้านทดลองให้ดู จากนั้นใช้แปลนและภาพของคุณสร้างบ้านจริงทีละรอบ

ZIP นี้ไม่ได้ให้สิทธิ์เข้าถึงเครื่องแทนคุณ และแต่ละบัญชีอาจมีชื่อรุ่น/เครื่องมือต่างกัน ถ้า AI มองไม่เห็นไฟล์ ให้แนบไฟล์หรือเลือกโฟลเดอร์ในแอป ไม่ต้องให้รหัสผ่าน ถ้าไม่มีเครื่องมือรันเว็บ AI ต้องบอกข้อจำกัดและส่งไฟล์ให้เปิดในสภาพแวดล้อมที่รันได้ ไม่อ้างว่าเปิดตรวจแล้ว

**อยากเห็นของก่อน:** ให้ AI รัน `node starter/serve.mjs` แล้วเปิด `http://127.0.0.1:4328/` มีบ้านสมมติที่หมุน แยกชั้น ปรับผนัง เปลี่ยน SD/HD และเลือกห้องได้ ไม่ต้องติดตั้ง package เพื่อเปิดตัวอย่างครั้งแรก มี Node.js 18 ขึ้นไปก็รันได้

**เตรียมเท่าที่มี:** แปลนแต่ละชั้น 1 ไฟล์ขึ้นไป + ภาพหลัก 6–12 มุม + บอกด้านหน้าบ้าน/ทางเข้าหลัก หากไม่มีครบ AI เริ่มทำส่วนที่มีหลักฐานได้ และทำรายการรอยืนยันเฉพาะจุด ไม่บังคับคุณกรอกทุกช่องก่อนเห็นงาน

ต้นฉบับอยู่ใน `MY-HOUSE/` ซึ่ง server ตัวอย่างไม่เปิดให้ดาวน์โหลด งานที่จะเผยแพร่แยกเป็น `OUTPUT/site/` เสมอ อย่าอัปโหลดทั้งโฟลเดอร์โปรเจกต์ขึ้นเว็บ

ใช้หลักอาจารย์ทีม: ใช้ข้อมูลอะไร / ถูกคืออะไร / ผิดแล้วแก้ตรงไหน ทำงานให้ฉันดูจริง ไม่จบแค่แผนหรือโยนโค้ดยาวให้ฉันไปประกอบเอง

เริ่มเปิด starter บ้านสมมติให้ฉันเห็นและลองเล่นก่อน ใช้ node starter/serve.mjs ถ้ารันได้ จากนั้นทำสารบัญหลักฐานจากแปลนและภาพที่ฉันให้ ถามเฉพาะข้อมูลที่ขวางงานจริงไม่เกิน 3 ข้อ แล้วทำทรงบ้าน+ชั้น+ทางเข้ารอบแรกเป็น preview ให้ฉันตรวจ

เป้าหมายคือประสบการณ์สำรวจบ้านแบบ https://www.myclover.com/showcase/house/ ด้วยข้อมูลและบุคลิกของบ้านฉัน: ทั้งหลัง/เลือกชั้น/แยกชั้น, โมเดล/แปลน/รูปจริง, เลือกห้อง, Full/Auto/Low, บิลต์อินกับเฟอร์นิเจอร์แยกกัน, SD เริ่มต้น/HD เลือกเปิด, กล้องไม่กระโดด และมือถือใช้ง่าย ไม่คัดลอกเรื่องครอบครัว สี ภาพ โลโก้ แปลน หรือกุญแจหลังบ้านของตัวอย่าง

ฉันอนุญาตให้อ่านไฟล์ที่ฉันเลือกและสร้าง/แก้ไฟล์งานภายใน OUTPUT/ และสำเนา starter สำหรับงานนี้ ผ่านเครื่องมือที่แอปให้สิทธิ์จริง ให้คงต้นฉบับ MY-HOUSE/ ไว้ ยังไม่อนุญาตเผยแพร่ ส่งไฟล์ให้บุคคลอื่น ซื้อบริการ หรือต่อ analytics เอง

บันทึกหลักฐาน ล็อกสิ่งที่ฉันยืนยัน และประวัติแก้ใน OUTPUT/ ทุกครั้ง ถ้าคุณรันหรือมองภาพไม่ได้ ให้บอกตรง ๆ และทำส่วนอื่นที่ทำได้ก่อน จนได้งานที่เปิดตรวจได้ รายงานสั้น ๆ ว่าเสร็จอะไร เปิดที่ไหน รอฉันยืนยันจุดใด

# ขวด 1 · SOURCE — ดูบ้านจากหลักฐาน

**ใส่อะไร:** แปลน ภาพ และคำอธิบายเจ้าของบ้าน
**ได้อะไร:** `OUTPUT/01-evidence.md` และ `OUTPUT/02-house-spec.md`

หลักอาจารย์ทีม: ส่งซอสต้องมีทั้งข้อมูล เกณฑ์ตรวจ และวิธีแก้ ไม่ใช่ prompt วิเศษที่สั่งแล้วจบ นี่คือการประยุกต์หลักการใน SAUCE.md ไม่ใช่คำพูดตรงทุกประโยคของอาจารย์

สำหรับ AI:
- เปิดดูไฟล์ที่ได้รับจริง ระบุไฟล์/หน้า PDF/มุมภาพที่อ่านแล้วและที่ยังอ่านไม่ได้ ใช้แบบฟอร์มใน MY-HOUSE/NOTES.md เป็นจุดเริ่ม ไม่ให้คนกรอกซ้ำถ้าดูจากไฟล์ได้
- แยก SOURCE (เห็นในไฟล์/เจ้าของยืนยัน), DERIVED (ข้อเสนอและค่าประมาณ), OPEN (ยังไม่รู้) ใช้ ID S01, S02… อ้างได้กลับไปที่ไฟล์และหน้า
- แปลนเป็นฐานห้อง/ทางเดิน/ช่องเปิด ภาพและคำยืนยันเจ้าของเป็นฐานรายละเอียดที่อยู่จริง เช่น บิลต์อิน โซฟา เตียง หน้าต่างที่เปลี่ยนจากแปลน หากขัดกันให้บันทึกทั้งสองและขอคำยืนยันเฉพาะจุด ไม่เลือกเงียบ ๆ
- สร้างตารางภาพ → ห้อง + สถานะ confirmed/candidate/context ภาพที่ไม่แน่ใจแสดงเป็นชุดภาพแยก ห้ามปักห้องเอง รูปโดรนช่วยทิศหลังคา/โซลาร์ ไม่แทนภาพภายใน
- กำหนดแกนเดียว: X ซ้าย–ขวา, Y ความสูง, Z หน้า–หลัง; จุดกำเนิด/สเกล/ด้านหน้าบ้าน/ระดับชั้นต้องบันทึกชัด ทุกชั้นใช้แกนเดียวกัน
- ไฟล์ไม่ครบให้เริ่มจากทรงบ้านสมมติที่ระบุชัด หรือส่วนที่เห็นจริง ไม่สร้างรายละเอียดแล้วอ้างว่าเป็นบ้านจริง

**ตรวจว่าถูก:** เจ้าของชี้หน้าบ้าน ทางเข้า บันได และตำแหน่งห้องหลักได้ตรงกัน มีประตูเข้าออกต่อถึงกัน; ระยะที่ไม่ทราบมีป้ายประมาณ
**ถ้าผิด:** กลับไปแก้ตารางหลักฐาน/ทิศ/สเกลก่อนแก้เฟอร์นิเจอร์ อย่าหมุนหรือขยับบางห้องเพื่อกลบปัญหาแกนทั้งชั้น

# ขวด 2 · TASTE — ให้เจ้าของชิมก่อนทำทั้งหลัง

**ใส่อะไร:** สเปกบ้าน + ภาพหลักที่ยืนยัน
**ได้อะไร:** preview ทรงบ้านทั้งหลัง + ห้องสำคัญ 1 ห้อง + `OUTPUT/03-locked-decisions.md`

สำหรับ AI:
1. สำเนา starter ไป `OUTPUT/site/` ใช้ห้องสมมติเพียงทดสอบ engine แล้วแทนด้วยข้อมูลบ้านใหม่ ไม่ปรับบ้านจริงให้พอดีกับเลขตัวอย่าง
2. ทำโครงบ้าน สัดส่วนบนจอ และชั้นที่ต่อกันก่อน หลังคา/โซลาร์ต้องอยู่ด้านที่หลักฐานบอก เปิดมุมหน้าบ้านและมุมบนให้เจ้าของดู
3. เลือกห้องที่มีภาพชัด 1 ห้อง ลองแสง วัสดุ และเฟอร์นิเจอร์เฉพาะห้องนั้น SD/HD ใช้ผังและช่องเปิดชุดเดียวกัน
4. ถามสั้น ๆ ว่า “ทรงบ้าน ทางเข้า และอารมณ์ห้องนี้ใช่ไหม” พร้อมภาพ/preview ที่กดได้ ไม่ส่งตัวเลือกยาวหลายแนวและรอให้ผู้เริ่มต้นออกแบบเองทั้งหมด
5. บันทึกสิ่งที่ยืนยันไว้ ล็อกชื่อห้อง ประตู หัวเตียง ทิศโซฟา บิลต์อินสำคัญ ไม่เปลี่ยนอีกเมื่อเพิ่ม HD

**ตรวจว่าถูก:** บ้านต่อสนิท ชั้นไม่ลอย ผังอ่านง่าย และเจ้าของรู้สึกว่าเป็นบ้านของตน อนุญาตจัดสัดส่วนเพื่อดูสวยบนจอ แต่ต้องไม่ทำให้ทางเดิน/ประตูผิดหน้าที่
**ถ้าผิด:** ขอ screenshot วงจุด หรือคำอธิบายหนึ่งจุด แก้เฉพาะจุดแล้วเทียบมุมเดิม เก็บส่วนที่ผ่านไว้

# ขวด 3 · COOK — ประกอบบ้านที่เล่นได้จริง

**ใส่อะไร:** ผังที่ผ่านรอบแรก + ล็อกการตัดสินใจ
**ได้อะไร:** โมเดลทั้งหลังใน `OUTPUT/site/`

โครงที่ AI ควรรักษา: ข้อมูลบ้าน / geometry / วัสดุ / state / UI แยกกัน แก้ข้อมูลก่อนแก้ mesh กระจัดกระจาย ใช้ starter เป็นเครื่องยนต์เริ่มต้น ไม่อ้างว่าเป็น engine เวอร์ชันเต็มของบ้านตัวอย่าง

- ห้องทุกห้องมี stable ID, floor ID, polygon/ขอบเขต และชื่อ; พื้นที่เปียก โถง บันได ที่จอดรถ แยกบทบาท
- ผนังร่วมมีเจ้าของเดียว ช่องประตูและหน้าต่างเป็น opening บนผนัง ไม่เอาบานโปร่งใสทับผนังทึบ หน้าต่างขนาดเต็มต้องอิงภาพจริง
- ทำ circulation graph ว่าประตูใดเชื่อมห้องใด ตรวจว่าทุกห้องที่ใช้งานเข้าถึงได้จากทางเข้าหลัก ห้ามเพิ่มประตูเพียงเพื่อให้สวย
- บันไดอยู่ในกลุ่มชั้นของตน ช่องเปิดพื้นชั้นบนต้องเว้นจริง ไม่ให้แผ่นพื้นเต็มตัดผ่านบันได แชนเดอเลียร์/โถงสูงแบ่งชิ้นตามระดับชั้นเมื่อแยกชั้น
- เฟอร์นิเจอร์ใช้ local transform ของห้อง เก้าอี้หันเข้าหาโต๊ะ หัวเตียง โซฟา โต๊ะทำงานอิงคำยืนยัน ไม่ใช้สีหรือเฟอร์นิเจอร์เป็นข้ออ้างเปลี่ยนผัง
- แยก wall / glazing / railings / builtins / furniture / roof ให้ปุ่มผนังลดเฉพาะผนัง ไม่ทำราว บิลต์อิน เตียง หรือโคมหาย
- ทั้งหลังประกอบสนิท เลือกชั้นแสดงชั้นนั้น แยกชั้นย้าย group ด้วย offset ชั่วคราว ไม่แก้พิกัดจริงซ้ำไปเรื่อย ๆ

**ตรวจว่าถูก:** สลับทั้งหลัง→ชั้น 1→ชั้น 2→แยกชั้น 20 รอบแล้วตำแหน่งเดิมไม่เลื่อน ห้องน้ำมีสุขภัณฑ์ที่หลักฐานรองรับ ไม่มีเสาหรือพื้น coplanar ซ้อนกะพริบ
**ถ้าผิด:** แก้ ownership / datum / ผนังร่วมต้นทาง ห้ามดันผิวออกด้วยค่ามั่วทุกครั้งจนอาคารบวม

# ขวด 5 · SEASON — แต่งให้ว้าว โดยรักษาบ้านเดิม

**ใส่อะไร:** ผังและอารมณ์ที่เจ้าของชิมผ่าน
**ได้อะไร:** SD เริ่มต้น + HD เลือกเปิด และประสบการณ์มือถือ

- รักษา SD ที่เปิดเร็วเป็นค่าเริ่มต้น HD เพิ่มวัสดุผิวหยาบ/มัน แสงสะท้อน เงา รายละเอียดขอบ/ผ้า/กระจก โดยใช้ room anchors และช่องเปิดเดิม สลับแล้วต้องเก็บ position, target และ zoom ของกล้อง
- อย่าอ้างว่ารายละเอียดสูง = แค่เพิ่มความสว่าง/ความอิ่มสี starter มีเพียง HD ขั้นต้น (เงา+วัสดุ+ความละเอียดการวาด) งานจริงต้องเติมรายละเอียดจากภาพตามขวด 2–3
- เริ่มจากแสงดีและเงาชัดก่อนเพิ่ม polygon; ทำ texture ซ้ำใช้ร่วมกัน จำกัด pixel ratio และขนาด shadow map ให้เหมาะมือถือ โหลดของหนักเฉพาะตอนเปิด HD; มี fallback SD ถ้าล้มเหลว
- แสดงผนัง Full / Auto / Low ใกล้ปุ่มชั้น กดครั้งเดียวเห็นผล Auto หลบฝั่งที่บังกล้อง เมื่อดูทั้งหลังมี “เปิดดูข้างใน” ไม่ทำให้หลังคาหายเอง
- แยกเลเยอร์บิลต์อิน/เฟอร์นิเจอร์ ปุ่มหลักกดอย่างน้อย 44px บนมือถือ ปรับ canvas ให้รับ 2 นิ้วซูม/เลื่อนโดยไม่ทำให้ทั้งหน้ากระโดด ไม่ใช้ล็อกซูมทั้งเว็บเพื่อกลบ layout ที่ล้น
- บ้านเป็นพระเอก ข้อความน้อย ไม่มีหน้าต้อนรับเต็มจอ ถ้าทำคำแนะนำให้ปรากฏหลังโมเดลพร้อม แสดงครั้งเดียวและเปิดเองได้อีก เคารพ reduced motion

**ตรวจว่าถูก:** เทียบ SD/HD มุมเดียวกัน ผังไม่เปลี่ยน; ปรับผนังไม่ล้างห้อง; ซูมใกล้แล้วไม่ตัดบ้านผิดปกติ; ตรวจ 360/390px และแนวนอนจริงใน browser/จำลองพร้อมบอกตามจริง
**ถ้าผิด:** ลด draw calls/ใช้วัสดุร่วม/หยุด render เมื่อ idle ก่อนลดคุณภาพทั้งภาพ ปรับระยะกล้องและ clipping จาก bounds ไม่แก้ด้วย scale บ้านทั้งหลัง

# ขวด 6 · SERVE — ส่งงานที่เปิดใช้ได้ และรับช่วงต่อได้

**ใส่อะไร:** preview ที่เจ้าของตรวจแล้ว
**ได้อะไร:** งานพร้อมเผยแพร่ + `OUTPUT/04-QA.md` + `OUTPUT/05-NEXT.md`

ก่อนส่ง AI ต้องเปิดและตรวจจริงตามเครื่องมือที่มี:
- อ่าน source / build workflow แล้ว build จาก source ไม่แก้ bundle อย่างเดียว
- ทั้งหลัง → ชั้น 1 → ห้อง → แปลน → รูป → โมเดล → ชั้น 2 → ทั้งหลัง, SD↔HD มุมกล้องคงเดิม, ผนัง/เลเยอร์/แยกชั้น, refresh/back/forward/deep link
- ตรวจ console error, network ไฟล์หาย, touch/keyboard/focus, ไม่มี horizontal overflow และภาพแต่ละห้องตรง binding
- ทดสอบ geometry ที่เสี่ยง: ประตูไม่ชนผนัง ช่องพื้นบันได ผนังร่วม เสาซ้อน และการแยกชั้น ไม่เขียนเทสต์ที่แค่ตรวจว่าโค้ดมีคำหนึ่งอยู่
- ภาพ OG 1200×630 ใช้ภาพที่เจ้าของอนุญาต ตัวอักษรจริงคมชัด title/meta อยู่ใน HTML ไม่อาศัย runtime; ไม่ใช้โลโก้/เรื่องบ้านของ myClover เป็นของผู้รับ
- สรุปเป็น ผ่าน / ยังไม่ได้ตรวจ / ต้องแก้ พร้อม URL ภาพหน้าจอ และคำสั่งที่รันจริง ไม่รับรอง “พร้อมแชร์” หากยังเปิดไม่ได้

**การเผยแพร่เป็นขั้นสุดท้าย:** ZIP ไม่ใช่คำอนุญาต deploy ให้ส่ง preview ที่ตรวจแล้วก่อน ถ้าเจ้าของอนุญาตชัดในงานนี้จึงเผยแพร่ตามแพลตฟอร์มของเขา ตรวจ live ใหม่และแยกสถานะ preview / production ห้ามคัดลอกระบบรหัสหลังบ้าน analytics ฐานข้อมูล หรือ credential ของตัวอย่างไปด้วย

ส่งไฟล์ source + built output + วิธีรัน + versions + หลักฐาน + OPEN และระบุสิ่งที่ห้ามเปลี่ยน ให้แชตถัดไปเริ่มต่อได้โดยไม่ต้องเดาความจำเดิม ความสามารถในการสร้างเกิดจากวัตถุดิบและการตรวจแก้ ไม่ใช่การดาวน์โหลด ZIP เพียงอย่างเดียว

**ถ้าจะหยุดพัก:** อัปเดต `OUTPUT/05-NEXT.md` ว่าเสร็จอะไร คำสั่งรันล่าสุด เปิดที่ไหน และงานถัดไปข้อแรก ไม่อ้างว่าใครทำสำเร็จแทนหลักฐาน

# ผิดตรงไหน ส่งคำสั่งสั้น ๆ แบบนี้

“ที่ [ชั้น/ห้อง/จุดในภาพ] ตอนนี้ [สิ่งที่เห็นผิด] ของจริงคือ [ข้อมูลที่ยืนยัน] ดูไฟล์ [ชื่อ/หน้า/รูป] แก้เฉพาะจุดนี้ ล็อกส่วนที่ผ่านไว้ เปิดมุมเดิมให้เทียบ แล้วอัปเดตหลักฐานกับ QA”

| อาการ | เริ่มหาที่ไหน | อย่าแก้ด้วย |
|---|---|---|
| ชั้นสองลอย/เหลื่อม | datum และ group transform | ยืดชั้นล่างกลบช่อง |
| ห้องไม่มีทางเข้า | ตารางประตู + circulation | เพิ่มประตูที่ไม่มีจริง |
| เสาหรือกระจกกะพริบ | mesh ซ้อน / depth / ผิว coplanar | เพิ่มแสงให้มองไม่เห็น |
| หัวเตียง/เก้าอี้กลับด้าน | local axes และ facing ของชิ้นนั้น | หมุนทั้งห้อง |
| Solar สลับหน้าหลัง | ทิศหลังคาจากภาพโดรน | เดาจากมุมกล้องบนเว็บ |
| HD ย้ายกล้อง | quality switch จับ camera pose | fit ทั้งบ้านใหม่ทุกครั้ง |
| รูปอยู่ผิดห้อง | confirmed/candidate/context | จับคู่จากความสวย |
| AI บอกเปิดเว็บแล้วแต่ไม่มี URL | เครื่องมือจริงและผลรัน | เชื่อคำรายงานแทนการเปิดดู |

ถ้าขอแก้หนึ่งจุดแล้ว AI เปลี่ยนทั้งเว็บ ให้ส่ง `OUTPUT/03-locked-decisions.md` กลับไป พร้อมย้ำว่าจุดที่ผ่านต้องคงเดิม
