# สั่งงานหนึ่งชิ้น — ให้ไปถึงฉบับที่ใช้ตรวจได้

## วิธีใช้และขอบเขต

**ใช้กับ:** AI ที่ทำงานชนิดที่เลือกได้ และคนในทีมที่รับบรีฟไปทำงานต่อ

**ใส่อะไร:** `01-source-index.md`, `02-organization-source.md`, กติกาจาก `03-style-and-quality.md` เท่าที่เกี่ยวข้อง และงานจริงหนึ่งเรื่องที่มีผู้รับชัด

**ได้อะไร:** `04-work-brief.md` — ซอสลูกสำหรับงานหนึ่งชิ้น ระบุผู้รับ วัตถุดิบ ขอบเขต เกณฑ์เสร็จ และวิธีทำฉบับแรกให้ตรวจได้

**เชื่อมบทเรียน:** บท 3 · COOK — `/classroom/clip-ai.html`; แนวคิดซอสลูกใน `/classroom/free-ai.html`; ทำจานจริงใน `/course/`; คำสั่งงานตามประเภทใน `/classroom/prompts.html`

**ทำก่อน:** ใช้สูตร `org-source-map` และ `org-core-source` หรือมีข้อมูลเทียบเท่า ใช้ `org-taste-check` เมื่อมีน้ำเสียง ภาพ หรือส่วนที่ต้องล็อก ถ้ายังไม่มีแนวทางสไตล์ ใช้รูปแบบกลางที่อ่านง่ายและระบุว่ารอตรวจได้

งานแรกอาจเป็นสรุปประชุม คู่มือขั้นตอนเดียว ข้อความต้อนรับผู้รับบริการ แผนอบรมหนึ่งช่วง หรือเอกสารแนะนำโครงการ เลือกเพียงหนึ่งชิ้นที่ผู้รับจะเปิดดูและให้ feedback ได้ ไม่ต้องทำทุกช่องทางพร้อมกัน

บท COOK ปัจจุบันฝึกวิดีโอเล่าเรื่องชีวิตจาก Source และภาพของผู้เรียน สูตรนี้ขยายหลักการสั่งทำงานหนึ่งชิ้นไปสู่งานองค์กร เป็นการประยุกต์ใหม่ ไม่ได้อ้างว่างานองค์กรทั้งหมดเป็นการบ้านเดิมหรือว่าต้องใช้วิดีโอ การใช้ AI ตัวใดขึ้นกับชนิดงาน ความสามารถที่มีจริง และสิทธิใช้วัตถุดิบ

## เนื้อหาหลัก

### SOURCE — หลักจากต้นทางที่นำมาใช้

- `/course/` เสนอให้เริ่มจากวัตถุดิบของผู้เรียน สกัด Source หลัก และเลือกผลงานที่ต้องใช้จริงหนึ่งชิ้น ระดับที่ทำได้ขึ้นกับงานและวัตถุดิบ ไม่ใช่คำรับประกันผลงานทุกประเภท [S01]
- Main Source ใช้ต่อข้ามงานได้ ส่วน Task Source กำหนดบริบทของงานเฉพาะชิ้น [S02]
- เส้นทาง COOK ที่ใช้งานอยู่มี Source ของงาน มีข้อกำหนดชิ้นงานที่ตรวจได้ และให้ชิมแล้วแก้ การอัดเสียง ถ่ายเอง หรือตัดต่อเพิ่มไม่ใช่ข้อบังคับทุกงาน [S03]
- คำสั่งประชุมแยกข้อตกลง งาน ผู้รับผิดชอบ และกำหนดส่ง; SOP แยกขั้นตอน เกณฑ์ตรวจ ข้อยกเว้น และการส่งต่อ; งานรายงานต้องแยกข้อเท็จจริงกับการตีความ ข้อมูลที่ไม่มีห้ามเดาเติม [S04]

### DERIVED — วิธีทำทีละขั้นสำหรับองค์กร

1. **ตั้งงานด้วยผู้รับและการใช้จริง** เขียนประโยคว่า “ทำ [ชิ้นงานหนึ่งชิ้น] ให้ [ใคร] เพื่อให้ [เข้าใจหรือลงมืออะไร]” เช่น เอกสารต้อนรับผู้ใช้พื้นที่ครั้งแรกเพื่อรู้ว่าจะเริ่มที่จุดไหน
2. **ลดขอบเขตให้มีฉบับแรกหนึ่งชิ้น** ระบุประเภทไฟล์และจำนวนส่วนที่จำเป็น ตัดงานที่ยังไม่ต้องทำออกอย่างชัดเจน เช่น ทำคู่มือขั้นตอนต้อนรับหนึ่งหน้า ยังไม่ทำระบบลงทะเบียนหรือแคมเปญทั้งชุด
3. **เลือกวัตถุดิบเท่าที่ใช้** อ้าง Source ID และเวอร์ชันจากทะเบียน พร้อมข้อความหรือตำแหน่งที่เกี่ยวข้อง ชิ้นงานย่อยไม่ควรกลายเป็น Source ข้อเท็จจริงอีกชุดที่แก้แข่งกับซอสแม่
4. **ใส่ทรัพยากรและข้อจำกัดจริง** ใครทำ ใครตรวจ มีเครื่องมือหรือไฟล์ใด ใช้ช่องทางอะไร กำหนดส่งมีจริงหรือยัง ไม่สมมติว่า AI เข้าไดรฟ์ ส่งเมล สร้างวิดีโอ หรือเผยแพร่ได้ถ้าไม่มีความสามารถและสิทธิในงานนี้
5. **กำหนดเกณฑ์เสร็จก่อนสั่งทำ** ผู้รับต้องหาอะไรเจอ ข้อเท็จจริงใดต้องตรง รูปแบบใดต้องเปิดได้ มีลิงก์หรือปุ่มใดต้องทำงาน และใครเป็นผู้ตรวจ กำหนดเฉพาะสิ่งที่สัมพันธ์กับงาน
6. **สั่งทำฉบับแรกจากข้อมูลที่พอแล้ว** ใช้ข้อความสั่งงานท้ายสูตร สร้างส่วนที่มีหลักฐาน ระบุเรื่องที่ยังไม่รู้ ถ้าข้อมูลจำเป็นต่อความถูกต้องของส่วนหนึ่งให้พักส่วนนั้นแทนการแต่งคำตอบ
7. **เปิดตรวจตามรูปแบบจริง** อ่านเอกสาร เปิดภาพ เล่นคลิป หรือกดเส้นทางที่เกี่ยวข้อง หากยังไม่ได้ลอง ให้บันทึกตามจริงและระบุสิ่งที่ต้องตรวจต่อ ใช้กติกาจาก `03-style-and-quality.md` แก้เฉพาะส่วนที่ผิด
8. **บันทึกฉบับที่ส่งตรวจและเจ้าของขั้นถัดไป** อ้างชิ้นงานด้วยชื่อและเวอร์ชันเดียว ระบุข้อจำกัด งานค้าง และผู้พิจารณา การส่งไฟล์ให้ผู้ตรวจภายในไม่เท่ากับอนุญาตเผยแพร่หรือส่งข้อความออกไปหาคนนอก

เลือกโครงให้ตรงงาน: สรุปประชุมใช้ ข้อตกลง → งาน/ผู้รับผิดชอบ/กำหนด → เรื่องค้าง; SOP ใช้ จุดประสงค์ → สิ่งเตรียม → ขั้นตอน → เกณฑ์ตรวจ → ข้อยกเว้น; สื่อต้อนรับใช้ ใครใช้ → เริ่มอย่างไร → สิ่งที่ต้องรู้ → ขั้นต่อไป; แผนอบรมใช้ ผู้เรียน → เป้าหมาย → กิจกรรม → สิ่งที่ส่ง → วิธีตรวจ เหล่านี้เป็นโครงประยุกต์ที่ต้องปรับตาม Source จริง

### ทางเลือกภาพและวิดีโอ

ถ้างานจริงต้องใช้โปสเตอร์ ให้ระบุผู้รับ ใจความที่ต้องเห็น ขนาดสำหรับช่องทางที่เลือก และภาพอ้างอิงที่มีสิทธิใช้ ถ้าต้องใช้วิดีโอ ให้เพิ่มลำดับภาพ ความยาวจริง ข้อความหรือเสียงที่ต้องมี และวิธีตรวจว่าเล่นได้ เลือกรูปแบบตามงาน; 9:16 และไม่เกิน 10 วินาทีเป็นข้อกำหนดของแบบฝึก COOK เดิม ไม่ใช่กฎของสื่อองค์กรทุกชิ้น

ไม่ต้องอัดเสียงหรือถ่ายภาพใหม่ถ้างานไม่จำเป็น อย่าทำภาพบุคคล อาคาร หรือเหตุการณ์สมมติแล้วอ้างว่าเป็นหลักฐานจริงขององค์กร และอย่าให้การเพิ่มสื่อทำให้งานฉบับแรกบานออกเป็นหลายชิ้น

### ตัวอย่างสมมติ — คู่มือต้อนรับหนึ่งหน้า

กลุ่มดูแลห้องกิจกรรมสมมติต้องการเอกสารให้ผู้มาใช้พื้นที่ครั้งแรก คู่มือที่ผู้ดูแลยืนยันแล้ว [S01 รุ่น 2 หัวข้อ 3] มีสามขั้น: แจ้งผู้ดูแล → ลงชื่อในรายการ → รับคำแนะนำจุดใช้งาน ยังไม่ได้ส่งข้อมูลเวลาเปิดหรือช่องทางติดต่อ

บรีฟฉบับแรกเลือก `welcome-guide.md@0.1.0` หนึ่งหน้า มีคำต้อนรับ ขั้นตอนสามข้อ และข้อสังเกตภายในว่าข้อมูลเวลาเปิดยังรอยืนยัน ผู้รับตรวจคือผู้ดูแลพื้นที่ ขอบเขตยังไม่รวมระบบลงทะเบียน โปสเตอร์ และวิดีโอ

ข้อความทดลองจากข้อมูลที่มี: “ยินดีต้อนรับสู่ห้องกิจกรรม เมื่อมาถึง ให้แจ้งผู้ดูแล ลงชื่อในรายการ แล้วรับคำแนะนำจุดใช้งานก่อนเริ่มกิจกรรม”

เกณฑ์ตรวจคือผู้ตรวจชี้ขั้นตอนแรกได้ ลำดับสามข้อเหมือน S01 ไม่มีเวลาหรือช่องทางที่แต่งเพิ่ม และเปิดไฟล์อ่านข้อความครบได้ สถานะการเปิดไฟล์ยังเป็น “ยังไม่ได้ตรวจ” จนกว่าจะมีผู้เปิดจริง เรื่องเวลาเปิดไม่ขวางการเขียนสามขั้น แต่ต้องมีผู้ยืนยันก่อนนำข้อมูลเวลามาเพิ่มในรุ่นต่อไป

ตัวอย่างนี้ไม่ใช่ข้อบังคับการต้อนรับขององค์กรทั่วไป และไม่ใช้แทนคู่มือจริงของผู้ใช้

## เกณฑ์ตรวจและวิธีแก้เมื่อผิด

| สิ่งที่ต้องผ่าน | อาการที่พบบ่อย | วิธีแก้ |
|---|---|---|
| มีผู้รับและการใช้หนึ่งเรื่อง | บรีฟขอ “ทำสื่อองค์กรให้ครบ” | เลือกผู้รับหนึ่งกลุ่ม งานแรกหนึ่งชิ้น และเกณฑ์เสร็จ |
| Source ย้อนตรวจได้ | คัดข้อมูลมาแต่ไม่บอกเวอร์ชัน | ใส่ Source ID/เวอร์ชัน/ตำแหน่ง และคืนข้อเท็จจริงไปแก้ที่ซอสแม่ |
| ทรัพยากรตรงความจริง | สมมติว่า AI มีไฟล์หรือสิทธิส่งงาน | ระบุสิ่งที่แนบและเครื่องมือที่มีจริง ทำส่วนที่ทำได้พร้อมบอกส่วนค้าง |
| ข้อมูลขาดไม่ถูกเติมเอง | ตั้งผู้รับผิดชอบ กำหนดส่ง หรือเงื่อนไขขึ้นใหม่ | เปลี่ยนเป็น OPEN/ยังไม่ระบุ และให้ผู้มีหน้าที่ยืนยัน |
| เกณฑ์เสร็จตรวจได้ | ใช้เพียง “สวย/มืออาชีพ/พร้อมใช้” | ระบุสิ่งที่ผู้รับต้องหาเจอ รูปแบบที่ต้องเปิดได้ และวิธีตรวจ |
| รายงานผลตรงการตรวจจริง | อ้างว่าไฟล์หรือปุ่มใช้งานได้จากการอ่านบรีฟ | เปิดหรือทดสอบจริง ถ้ายังทำไม่ได้ให้คงสถานะยังไม่ได้ตรวจ |
| การแก้ไม่ขยายงาน | ขอแก้หัวข้อแล้วเปลี่ยนรูปแบบทั้งชุด | ล็อกส่วนที่ผ่าน สั่งแก้เฉพาะจุด และตรวจผลกระทบที่เกี่ยวข้อง |

**ถือว่าบรีฟพร้อมใช้เมื่อ:** ระบุงานหนึ่งชิ้น ผู้รับ วัตถุดิบและเวอร์ชัน ขอบเขตจริง ทรัพยากร สิ่งที่ล็อก เกณฑ์เสร็จ ผู้ตรวจ และ OPEN ครบตามงาน ส่วนชิ้นงานจะถือว่าผ่านได้เมื่อมีผลตรวจที่เกิดขึ้นจริงและผู้รับผิดชอบยืนยันตามขอบเขตนั้น
