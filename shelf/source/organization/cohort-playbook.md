# 08 · เปิดครัวให้รุ่นถัดไป

## วิธีใช้และขอบเขต

**NEXT CLASS · รุ่นใหม่เริ่มจากสิ่งที่รุ่นก่อนเรียนรู้ แต่ยังต้องลองงานและตัดสินข้อมูลของตัวเอง**

- **ใช้กับ:** ผู้จัด ผู้เรียนเอง คู่ฝึก หรือทีมที่ต้องการทำซ้ำและส่งต่อการเรียนรู้
- **เชื่อมบทเรียน:** [ห้องเรียน 6 บท](/classroom/) และ [8 ขั้นของ Live Workshop](/course/)

ใช้วางกิจกรรมเรียนด้วยตนเอง เวิร์กช็อปทีม หรือการส่งต่อให้คนใหม่ในธุรกิจ โรงเรียน องค์กรไม่แสวงกำไร และทีมอื่น ๆ เป้าหมายคือมีซอสที่ตรวจแล้ว งานจริงหนึ่งชิ้น และวิธีทำต่อ ไม่ใช้จำนวนชั่วโมงหรือจำนวนคนเป็นหลักฐานแทนของที่ทำได้จริง

- **วัตถุดิบ:** สูตรกลางขวด 01–07, ชุดตัวอย่างที่อนุญาตให้ใช้, บันทึกผลลองใช้/ข้อผิดพลาด, โจทย์ผู้เรียน, เวลาและข้อจำกัดของกลุ่มนี้
- **ใช้คู่กับ:** [ห้องเรียน AI ใส่ซอส](/classroom/) และ [Live Workshop](/course/); ถ้ายังไม่มีผลจากรุ่นก่อน เริ่มด้วยตัวอย่างสมมติและระบุให้ชัด
- **สิ่งที่จะได้:** `08-cohort-playbook.md` ฉบับของรุ่นนั้น พร้อมแผนผู้จัด/ผู้เรียน เกณฑ์ร่วม หลักฐานก่อน–หลัง ผลฝึก Feedback และงานปรับรุ่นต่อไป
- **เริ่มอย่างไร:** เลือกงานเล็กที่ผู้เรียนต้องใช้จริงและมีวัตถุดิบอยู่แล้ว ทดลองเกณฑ์ร่วมบนตัวอย่างหนึ่งชิ้นก่อนปล่อยแต่ละคนทำงานของตน

สูตรนี้เป็น **DERIVED** จากวิธีเรียนเดิม ไม่ใช่ตารางคลาสที่ประกาศแล้ว ราคา วัน เวลา สถานที่ รายชื่อ และคำรับรองผลต้องมาจากผู้จัดจริง สูตรแปดขวดไม่ใช่การเปลี่ยนห้องเรียนเดิมให้กลายเป็นแปดบท

เปิดขวดนี้เพื่อวางแผนก่อนเริ่มเรียนได้ แต่สถานะ “จบรอบ/พร้อมส่งรุ่นถัดไป” ต้องรอให้มีซอส งานจริง ผลตรวจ และ handoff หลังครบวงจรแล้ว ช่องผลการเรียนรู้ที่ยังไม่เกิดต้องคงว่างหรือระบุ “ยังไม่ได้ทำ” การมีแผนไม่ใช่หลักฐานว่าผู้เรียนผ่าน

## เนื้อหาหลัก

### SOURCE · โครงเรียนที่มีอยู่จริง

ห้องเรียนเรียง **SOURCE → TASTE → COOK → SPLIT → SEASON → SERVE** งานในตัวอย่างปัจจุบันรวมซอสแม่ โปสเตอร์ชีวิต วิดีโอชีวิต งานหลายรูปแบบ สูตรร่วมงาน และ Smart Resume การนำไปใช้กับงานองค์กรเป็นการปรับโจทย์ของสูตรนี้ ไม่ใช่กล่าวว่าบทเรียนเดิมสอนข้อมูลขององค์กรนั้นอยู่แล้ว

S01 วาง 8 ขั้นของ Live Workshop: **เปิดตู้เย็น → เทวัตถุดิบ → เคี่ยวหัวซอส → คัดก้าง → ปรุงรส → ชิมแล้วแก้ → ทำจานจริง → บรรจุขวด** และตั้งผลกลับบ้านสามอย่างคือ Source หลัก ผลงานจริง และสูตรทำต่อ ผู้จัดช่วยฟัง จับข้อขัดแย้ง และให้ Feedback ระหว่างทำ

### DERIVED · ใช้ 8 ขั้นเวิร์กช็อปภายในรุ่นอย่างไร

แปดขั้นนี้เป็นจังหวะกิจกรรม จึงไม่ได้จับคู่หนึ่งต่อหนึ่งกับแปดขวด เช่น คัดก้างเกิดทั้งตอนทำขวด 01–02 และหลังได้ Feedback

| ขั้นจาก /course | ผู้จัดช่วยอะไร | ผู้เรียนทำอะไร | หลักฐานที่เก็บ |
|---|---|---|---|
| 1 เปิดตู้เย็น | ช่วยเลือกโจทย์เล็กและขอบเขตข้อมูล | ระบุวัตถุดิบที่มีจริง | ทะเบียนขวด 01 ฉบับเริ่ม |
| 2 เทวัตถุดิบ | ฟังเป้าหมายและสิ่งที่ยังไม่รู้ | เล่า/แนบไฟล์ที่มีสิทธิ์ใช้ | รายการอ่านแล้ว/ยังไม่อ่าน/OPEN |
| 3 เคี่ยวหัวซอส | ช่วยหาแกนที่ทุกงานต้องรักษา | สกัดบริบทและกติกา | ขวด 02 ร่างพร้อมอ้างอิง |
| 4 คัดก้าง | ชี้คำอ้างที่ไม่รองรับและข้อมูลชนกัน | แยกจริง/ข้อเสนอ/ล้าสมัย | รายการแก้พร้อมเหตุผล |
| 5 ปรุงรส | ชวนดูตัวอย่างผ่าน/ไม่ผ่าน | กำหนดเสียงและเกณฑ์ตัดสิน | ขวด 03 พร้อมตัวอย่าง |
| 6 ชิมแล้วแก้ | เทียบเกณฑ์ร่วมกับผลจริง | ทำชิ้นทดสอบ แยกสาเหตุผิด | ผลก่อนแก้/หลังแก้ + source version |
| 7 ทำจานจริง | ช่วยคุมขนาดงานและปลดจุดติด | ทำงานจากขวด 04 และเลือกแตกต่อผ่าน 05 | ไฟล์จริง + ผลตรวจ |
| 8 บรรจุขวด | ให้คนอื่นลองรับงานต่อ | จัดขวด 06–07 และสรุปการเรียนรู้ใน 08 | Workflow + handoff + เรื่องปรับรุ่นถัดไป |

### คำสั่งเริ่มงาน

> อ่านสูตร 8 ขวดและวัตถุดิบรุ่นนี้ที่แนบ สร้าง `08-cohort-playbook.md` สำหรับ [กลุ่ม] ในรูปแบบ [เรียนเอง/กลุ่ม] เชื่อมกับหกบท SOURCE–SERVE และแปดขั้นเวิร์กช็อปตามสูตร แยกแผนจากผลที่เกิดขึ้นจริง เตรียมเกณฑ์ร่วม ตัวอย่างชิมหนึ่งชิ้น งานจริงหนึ่งเรื่อง และวงจรฝึก–ตรวจ–Feedback–แก้ต้นทาง ใช้เวลา จำนวนคน และเครื่องมือเฉพาะที่เจ้าของระบุ ช่องว่างเป็น OPEN ไม่แต่งผลสำเร็จหรือ KPI ไม่มีหลักฐาน

### ปรับใช้เมื่อเรียนเองหรือเป็นกลุ่ม

- **เรียนเอง:** ผู้เรียนรับบทผู้จัดด้วย ใช้เกณฑ์เดียวตรวจงานก่อน–หลัง แล้วให้ผู้รับจริงลองงานอย่างน้อยหนึ่งช่วงเมื่อทำได้ ถ้ายังไม่มีคนลองให้บันทึกว่ารอ ไม่ติ๊กแทนเขา
- **เป็นกลุ่ม:** เริ่มเทียบตัวอย่างเดียวกันให้เข้าใจคำว่า “ผ่าน” ตรงกัน จากนั้นแยกงานของแต่ละคน ให้คู่ฝึกตรวจเฉพาะข้อมูลที่มีสิทธิ์อ่าน และส่งคำถามเชิงข้อเท็จจริงกลับเจ้าของข้อมูล
- **มีเวลาน้อย:** ลดขนาดจานจริงและจำนวนงานแตกต่อ คง Source, เกณฑ์, งานจริง และ handoff ไม่ตัดการตรวจเพื่อให้กิจกรรมจบตามเวลา

### ตัวอย่างสมมติขนาดเล็ก

กลุ่ม “ห้องแบ่งปัน” ฝึกทำคู่มือขอใช้ห้อง ผู้จัดให้ตัวอย่างที่เขียนว่าใช้ได้ทันทีทั้งที่ซอสระบุว่าต้องรอยืนยัน ผู้เรียนอธิบายจุดผิดจากหลักฐานเดียวกันก่อนแยกทำ FAQ ของตน หลังลองใช้พบคนใหม่ยังไม่รู้ว่าจะส่งคำขอให้ใคร จึงบันทึกเป็นข้อมูลขาดที่ต้องถามเจ้าของซอส

รุ่นถัดไปใช้กรณีนี้เป็นโจทย์ชิมได้เมื่อได้รับอนุญาต โดยลบข้อมูลเฉพาะบุคคล แต่ไม่สรุปว่า “ผู้เรียนทำงานเร็วขึ้นกี่เปอร์เซ็นต์” เพราะยังไม่มีการวัด ตัวอย่างทั้งหมดนี้เป็นสมมติ

## เกณฑ์ตรวจและวิธีแก้เมื่อผิด

| ตรวจอะไร | หลักฐานว่าผ่าน | วิธีแก้ |
|---|---|---|
| แยกสูตรกลางกับรุ่นจริง | ที่เก็บ สูตร@version และ cohort ID ชัด | ย้ายข้อมูลเฉพาะรุ่นออกจากสูตรกลางโดยรักษาประวัติ |
| ผู้เรียนเข้าใจเกณฑ์ตรงกัน | มีผลเทียบตัวอย่างและเหตุผลจาก Source | ชิมตัวอย่างร่วมอีกครั้งก่อนเพิ่มความยาก |
| มีผลงานจริง ไม่ใช่เพียงเข้าร่วม | เปิดซอส งาน และวิธีทำต่อที่ระบุฉบับได้ | ลดขอบเขตและทำให้ครบวงจรหนึ่งงาน |
| ผลก่อน–หลังเทียบได้ | งาน/เกณฑ์เดียวกันและมีไฟล์หลักฐาน | ระบุข้อจำกัดเมื่อ baseline ต่างหรือไม่มี ไม่คำนวณผลเกินหลักฐาน |
| Feedback กลับไปแก้ถูกจุด | มีสาเหตุ รายการแก้ และผลตรวจซ้ำ | แยกซอสขาด/งานผิด/คำตัดสินใหม่ก่อนแก้ |
| รุ่นถัดไปไม่รับข้อมูลเก่าผิด ๆ | รายการที่ใช้ซ้ำมี source/version และสิทธิ์ | ทบทวนตัวอย่างและข้อมูลที่เปลี่ยนก่อนเริ่มรุ่นใหม่ |
