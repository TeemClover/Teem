## หา / อัปเดต / ทำเพิ่ม

ค้น `catalog.json` จากชื่อ ID tag หรือชื่อไฟล์เดิมก่อน แล้วอ่านไฟล์จริง หากมีอยู่แล้วให้แก้ path เดิม บันทึกเวอร์ชัน วันที่ ที่มา และสิ่งที่เปลี่ยน หากเป็นเรื่องใหม่ให้เริ่มจาก [แม่แบบ](source/TEMPLATE.md) และเพิ่มรายการในสารบัญพร้อมกัน

- `products-offers.md` นำเข้าจาก `CLOVER_X_PRODUCTS_OFFERS_SOURCE_2026-09-09.md` โดยคงเนื้อหาและเวอร์ชัน 0.9 เดิม การนำเข้าวันที่ 2026-09-10 ไม่ใช่การรับรองข้อมูลใหม่
- `confirmation-questions.md` นำเข้าจาก `CLOVER_X_SOURCE_CONFIRMATION_QUESTIONS_2026-09-09.md` เพิ่ม metadata และลิงก์ที่ใช้ได้ใน Repo เป็น 0.9.1; เนื้อหาคำถามเดิมไม่เปลี่ยน
- Source เดิมที่ `/xircle/doc/source/` และที่อื่นยังอยู่ ไม่ได้ย้ายหรือลบทิ้ง
- `source/thedent/public-company.md` เป็นซอส The Dent พร้อมใช้กับข้อมูลและคำสั่งที่เตรียมไว้; `course/thedent/resources/clinic-public-source.md` เป็นสำเนาที่สร้างจากต้นฉบับนี้ เวอร์ชัน 0.2.0 ย่อจากหลักฐานที่ตรวจไว้วันที่ 2026-09-11 โดยไม่ได้ตรวจเว็บใหม่
- ไฟล์เสียง ภาพต้นฉบับ และ PDF ไม่ได้อัปโหลดเข้าชั้นนี้ในรอบนี้ ทะเบียนแหล่งในซอสอธิบายต้นทาง แต่ file ID จากแชทไม่ใช่ลิงก์สาธารณะใน Repo

## เวอร์ชันและสถานะ

ใช้ `MAJOR.MINOR.PATCH` สำหรับไฟล์ใหม่; ยอมรับเลข 0.9 ของต้นฉบับนำเข้าโดยไม่บังคับเปลี่ยนย้อนหลัง เพิ่ม PATCH เมื่อแก้รูปแบบ/ลิงก์ เพิ่ม MINOR เมื่อเติมข้อมูลที่อยู่ในขอบเขตเดิม และเพิ่ม MAJOR เมื่อเปลี่ยนขอบเขตหรือโครงสร้างที่กระทบผู้ใช้ต่อ การเพิ่มเลขเวอร์ชันไม่ยกระดับสถานะการยืนยันโดยอัตโนมัติ

เก็บ Git history เป็นประวัติ ห้าม force-push หรือเขียนทับความต่างโดยไม่มีบันทึก วันที่ของราคา/ข้อเสนอใช้เฉพาะที่ต้นทางยืนยัน ไม่อนุมานจากวันที่แก้ไฟล์

## ตรวจงาน

```sh
node shelf/validate.mjs
python3 -m http.server 8000
# เปิด http://localhost:8000/shelf/
```

หน้าเว็บเป็น static HTML ใช้ `catalog.json` สำหรับค้นหา กรองหมวด อ่าน คัดลอก และดาวน์โหลด `.md` ไม่ต้องเพิ่ม dependency หรือฐานข้อมูล

Repo นี้เปิดสาธารณะ ป้าย “รอยืนยัน” ไม่ใช่การจำกัดสิทธิ์เข้าถึง และเอกสารรวบรวมไม่ได้กลายเป็นเอกสารบริษัทอนุมัติด้วยการขึ้นชั้น
