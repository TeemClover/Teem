# ชั้นวางซอสแบบมีกุญแจ · 2.0.0

## วิธีที่ทีมใช้งาน

1. เปิด `/shelf/admin/` และเข้าด้วยรหัสหลังบ้าน myClover เดิม
2. เลือกผู้รับใหม่หรือคนเดิม ระบุอายุ 30 วัน / 90 วัน / ไม่หมดอายุ และให้สิทธิ์ทุกขวดหรือเลือกเป็นรายขวด
3. กุญแจเต็มแสดงครั้งเดียว คัดลอกส่งให้ผู้รับด้วยตัวเอง ระบบนี้ไม่ส่งข้อความหรืออีเมลแทนทีม
4. ผู้รับเปิด `/shelf/` กดแม่กุญแจ แล้ววางกุญแจ ระบบสร้าง session อายุไม่เกิน 7 วันและไม่เกินอายุกุญแจ กลับมาใส่กุญแจเดิมได้จนหมดอายุหรือถูกเพิกถอน
5. หลังบ้านแสดงผู้รับ ซอส และเวลา แยกคำขอเปิด คัดลอก ดาวน์โหลด ยอดรวมใช้ประวัติทั้งหมด รายการละเอียดแสดงล่าสุด 200 รายการ
6. กดเพิกถอนเพื่อหยุดกุญแจนั้น ทุกคำขอส่งซอสถัดไปจะถูกปฏิเสธ รวมถึงเบราว์เซอร์ที่เคยปลดล็อกแล้ว ออกกุญแจใหม่ให้ผู้รับคนเดิมได้โดยคงประวัติรายคน

กุญแจผูกกับชื่อผู้รับที่ทีมกำหนด เป็นหลักฐานการใช้กุญแจ ไม่ได้ยืนยันบุคคลด้วยอีเมลหรือบัญชีภายนอก หากส่งกุญแจต่อ การใช้งานยังรวมในชื่อเจ้าของกุญแจนั้น ไม่สามารถเรียกคืนไฟล์ที่ผู้รับเคยดาวน์โหลด หรือสังเกตสิ่งที่ผู้รับนำไปทำกับ AI ภายนอกได้

## สิ่งที่บันทึก

เมื่อเซิร์ฟเวอร์ตรวจสิทธิ์และเตรียมส่งซอสสำเร็จ จะบันทึกผู้รับ ID กุญแจ ID/ชื่อ/เวอร์ชันซอส ประเภทคำขอ และเวลา ไม่เก็บเนื้อหากุญแจจริงลงฐานข้อมูลหรือสถิติ ไม่มีการเก็บกุญแจหรือ session ลง localStorage

“ขอคัดลอก” และ “ขอดาวน์โหลด” หมายถึงระบบส่งเนื้อหาให้ตามคำขอนั้น ไม่ยืนยันว่าคลิปบอร์ดหรือการบันทึกไฟล์ของเครื่องสำเร็จ UI บอกผลฝั่งผู้รับแยกจากยอดฝั่งเซิร์ฟเวอร์ไว้แล้ว

## ขอบเขตการล็อก

- ซอสต้นฉบับยังเป็นไฟล์หลักใน `shelf/source/` และ catalog เดิม ไม่สร้างสำเนาเนื้อหาอีกชุด
- หน้าเว็บแสดงเฉพาะข้อมูลสารบัญย่อ ไม่มี path หรือเนื้อหาไฟล์ การส่งซอสใช้ POST `/api/shelf` พร้อม session ที่ผ่านการตรวจสิทธิ์
- `vercel.json` redirect ทาง `shelf/source/**` และ catalog ดิบกลับไปหน้าชั้น; middleware ครอบคลุมไฟล์ที่มีนามสกุลใน `/shelf/` และอนุญาตเฉพาะไฟล์หน้าจอที่กำหนด
- ฟังก์ชันอ่านเฉพาะ ID ใน catalog และตรวจ realpath ของไฟล์ให้อยู่ใต้ source root กุญแจหมดอายุ/เพิกถอน/ผิดขอบเขตไม่สามารถรับเนื้อหาได้
- ทั้งการอ่านและการบันทึกการส่งตรวจสิทธิ์ หากอ่านไฟล์หรือเขียนสถิติไม่ได้จะไม่ส่งเนื้อหาออก
- Repo นี้สาธารณะอยู่แล้ว รวมถึงประวัติ Git การล็อกทางเว็บไม่ลบสำเนาเก่าและไม่ใช่การทำให้ซอสเดิมเป็นข้อมูลลับ ถ้าจะมีซอสส่วนตัวในอนาคต ต้องจัดเก็บนอก repo สาธารณะก่อนเพิ่มเนื้อหา

## การเชื่อมระบบจริง

Production ใช้ `DATABASE_URL` ที่ระบบ myClover เดิมใช้ และ session จาก `/api/backoffice-auth` (`BACKOFFICE_ADMIN_KEY` เป็นค่ารหัสหลังบ้านที่ระบบเดิมรองรับ) ไม่มีรหัสใหม่ฝังในหน้าเว็บ ไม่มี fallback ไปใช้ฐานข้อมูลจำลองเมื่อระบบจริงขัดข้อง

ตารางใหม่อยู่ในกลุ่ม `mc_shelf_users`, `mc_shelf_keys`, `mc_shelf_sessions`, `mc_shelf_events`, `mc_shelf_login_hits` สร้างแบบ idempotent เฉพาะขอบเขต shelf ไม่เรียกตัวสร้าง schema ของระบบเกม/สมาชิกทั้งหมด ไฟล์ซอสถูกรวมเข้า `api/shelf.js` ด้วย `includeFiles: "shelf/{catalog.json,source/**}"`

ก่อนถือว่ารุ่นนี้พร้อมใช้จริง ต้องตรวจหลัง deploy ว่า endpoint/API และ cookie ใช้งานบน HTTPS ได้, path ดิบถูกปิดจริงบน Vercel, บทบาทหลังบ้านใช้งานได้ และการเพิกถอนหยุดคำขอใหม่ได้ การทดสอบในเครื่องไม่ใช่หลักฐานว่า config ขึ้นระบบออนไลน์แล้ว

อ้างอิงการจัดเส้นทางและการรวมไฟล์: [Vercel configuration](https://vercel.com/docs/project-configuration/vercel-json), [Routing Middleware](https://vercel.com/docs/routing-middleware)

## ทดลองในเครื่อง

```sh
npm run dev:shelf
# http://127.0.0.1:4188/shelf/
# http://127.0.0.1:4188/shelf/admin/
```

ตัวอย่างนี้ bind เฉพาะ loopback และติดป้าย LOCAL PREVIEW ใช้ฐานข้อมูลในหน่วยความจำและรหัสทดสอบ `shelf-local-review` โดยเฉพาะ การปิดตัวอย่างจะล้างข้อมูลทดลองทั้งหมด สร้างกุญแจทดลองผ่านหน้าหลังบ้านได้เอง ห้ามนำรหัสหรือ helper นี้ไปใช้ใน production (`tests/shelf/` ถูกตัดออกจาก deployment)

```sh
npm run test:shelf
# Optional real PostgreSQL-compatible local SQL test, without a production DB:
SHELF_PGLITE_MODULE=/absolute/path/to/@electric-sql/pglite/dist/index.js npm run test:shelf
node shelf/validate.mjs
```

หากไม่ได้ระบุ PGlite ชุดทดสอบ SQL จะรายงาน skipped อย่างชัดเจน ชุดสิทธิ์และหน้าเว็บยังทำงานได้โดยไม่เพิ่ม dependency ของ product
